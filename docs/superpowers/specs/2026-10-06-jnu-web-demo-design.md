# 호국실록 전남대 웹앱 설계

사용자 요청과 PRD를 구현 기준으로 삼는다. 환희의 HTML/Markdown 원본은 이동·수정·업로드하지 않는다. 앱은 `web/`에 만들며 작업 브랜치 `codex/jnu-web-demo`에서 제출한다.

## 제품과 화면

전남대 정문→용봉관, 네 명·네 역할의 협동 미션. 원본의 종이색·먹색·붉은 인장·한글 명조·인식표를 계승한다. 데스크톱은 코스 지도와 진행 패널, 휴대폰은 하나의 미션 흐름. 현장의 기억을 수집한다는 서사이며 군사적 표적·사격은 없다. 속도 경쟁은 추모 거점에만 두지 않으며, 그 밖에는 시간 점수·힌트 감점·팀 랭킹을 적용한다(2026-10-08 PM 정정, 상무대 필수 요구). 모든 버튼 44px 이상, 위치 거부·오프라인·재접속 안내, reduced-motion을 지원한다.

## 실행 구조

Next.js 16, React 19, TypeScript, Tailwind, Supabase Postgres·Realtime·Edge Functions, Vitest. 게임 규칙은 공통 서버 엔진에 둔다. 로컬 시연은 서버 파일에 상태를 원자 저장하고 단일 프로세스에서 직렬 처리한다. Supabase는 익명 JWT를 검증하며 서버 전용 JSON 상태와 공개 투영 테이블을 분리하고 버전 조건 갱신으로 충돌을 재시도한다. 클라이언트는 자기 단서·자기 숫자만 읽는다. 서비스 키와 정답은 클라이언트에 포함하지 않는다.

로컬 시연과 실데이터 환경은 명확히 표시한다. 혼자 체험하는 방은 시연 서버의 격리 방에만 허용하며, 명시적으로 보직을 바꿔 한 명씩 미션을 해결한다. 정상 4인 방의 권한·시간·시도를 우회하지 않는다. 외부 운영 배포와 실제 현장 검증은 계정·좌표·문항 확인 이후다.

## 데이터와 보안

공개 코스 자료·비공개 정답 파일을 시드 스크립트가 검증한다. 실제 모드에서는 confirmed=true, 유효 좌표, 모든 거점의 4역할 문항·답·숫자가 필요하다. answer_hash는 SHA-256(salt+site_id+role+정규화 답). 숫자는 서버 전용. 공용 상태는 보고✓·잠김 여부만. 실제 좌표 측위값은 서버에 전송·저장하지 않는다.

## 진행과 검증

4명 대기→무작위 보직 공개→장비 수령→이동→도착→4개 보고→지휘관 자물쇠→사초→다음 거점→종료. 방장·지휘관 권한을 분리한다. 자물쇠는 3회·오답 -10·소진 후 60초마다 1회, 맞은 칸 고정. 서버 상태와 요청 ID를 보관해 새로고침·재전송·경합으로 초기화되지 않는다. 수동 도착은 지휘관·이동 30초 이후. 초기 점수 100·최저 0 등 회의 제안 정책은 시연 설정으로 기록한다.

GPS는 정확도≤40m, 최근 유효 3표본 평균, 반경 내 5초. 고오차와 5초 초과 공백은 체류·표본을 초기화하는 보수적 임시 규칙이다. 실측 원본 확보 전 교차 검증 완료로 쓰지 않는다.

검증은 단위 테스트, 타입 검사, 빌드, 브라우저 네 세션의 두 거점 완주·정보 분리·권한·재시도·쿨다운, 360/390/1440 화면 확인. Supabase 실서비스·폰 4대·답사 검증은 실행 여부를 별도 기록한다.
