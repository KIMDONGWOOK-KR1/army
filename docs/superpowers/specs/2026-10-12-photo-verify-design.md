# 현장 사진 판정(Photo Verify) 설계

- 작성일: 2026-10-12
- 작성: 김동욱(PM, 인공지능 전공)
- 상태: 1단계 구현 완료(파이프라인·평가 도구·추론 서버). 평가셋 촬영 전이라 정확도 결과 없음. CPU 지연은 2단계 640px 축소 후 컨테이너 실측 p95 1.35초 이하(docs/LATENCY.md, Cloud Run 실측 전).

## 1. 배경과 목적

제안서에 있었던 "AI 사진 판정"은 1차 범위에서 빠지고 다음 단계 후보로 남았다([상무대 질의](../../meetings/2026-10-08-sangmudae-questions.md)). 사진 업로드는 D6(업로드·보관)과 G08(상무대 허용 조건)이 정해지지 않아 꺼져 있고, PR-6도 보류 중이다([BE_V2_PLAN](../../be/BE_V2_PLAN.md)).

이 설계는 **운영자가 미리 넣어 둔 기준 사진과 참가자가 찍은 사진이 같은 장소·대상인지** 판정하는 모델과 방법론을 정한다. 결과는 두 곳에 쓴다.

1. 논문: 방법 비교 실험과 성능 보고
2. 실제 앱: 거점 미션에 넣을 서버 판정기

## 2. 확정 조건

| 항목 | 결정 |
|---|---|
| 판정 의미 | 같은 장소·대상인지만 본다. 각도·거리·조명·날씨·사람 가림이 달라도 통과한다. 같은 구도로 다시 찍었는지나 세부 글자는 보지 않는다 |
| 실행 위치 | 서버에서 판정한다. 참가자 사진은 메모리에서만 처리하고 저장하지 않는다 |
| 정답 보호 | 기준 사진, 갤러리 특징, 임계값은 정답으로 취급한다. 클라이언트와 저장소에 두지 않는다 |
| 데이터 | 기준 사진은 거점당 1~5장이다. 학습 없이 사전학습 모델을 쓴다(zero-shot) |
| 외부 전송 | 2026-10-12 사용자 확인: 사진을 해외 리전·외부 업체로 보내는 것은 허용된다. 보관 허용은 아니므로 비저장 원칙은 유지한다 |
| 추론 서버 | 11절. Cloud Run 서울 리전(CPU)을 1순위로 하고, CPU 실측 p95가 2초를 넘으면 Modal GPU 서버리스로 옮긴다(GPU 이미지 변형 필요) |
| 부정행위 방지 | 기본 수준. 카메라 직접 촬영만 받고 GPS 도착 후에만 제출한다. 화면·인쇄물 재촬영 탐지는 범위 밖이다 |

## 3. 성공 기준 (가정, 평가 후 조정)

- 거점별 FAR ≤ 1%에서 TAR ≥ 90%
- 판정 1건 지연: CPU 기준 p95 ≤ 2초

평가셋을 촬영하기 전에는 성능을 주장하지 않는다. 실제로 측정한 값만 보고한다.

## 4. 방법론: 2단계 하이브리드

```
입력 사진 → 전처리·품질 검사 ──(불량)──→ RETAKE
              │
              ▼
   1단계 전역 임베딩(DINOv2+GeM) → 기준 갤러리와 코사인 유사도 s_g
              │ 상위 k개 기준 사진
              ▼
   2단계 국소 매칭(ALIKED+LightGlue) → MAGSAC++ 기하 검증 → inlier 수 n
              │
              ▼
   점수 결합 [s_g, log(1+n)] → 거점별 임계값 → MATCH / NO_MATCH
```

### 4.1 전처리
- EXIF 방향을 보정한 뒤 메타데이터를 모두 제거한다.
- 전역 단계는 짧은 변을 224px로 맞춘 뒤 가운데 224×224를 자른다(백본 간 입력 통일, ONNX 고정 입력). 국소 단계는 긴 변을 640px 이하로 줄인다(`local_long_side`, 지연 실측으로 1024px에서 낮춤. 값은 thresholds.json과 갤러리에 기록하고 다르면 서버가 시작을 거부한다). 품질 검사는 1024px 이미지에서 한다.
- 픽셀 수가 4천만을 넘거나 짧은 변이 64px 미만이면 디코딩 전에 `INVALID_IMAGE`로 거절한다. 품질 기본값은 흐림 하한 60, 밝기 25~235이고 평가셋으로 조정한다.
- 품질 검사: Laplacian 분산이 하한보다 낮으면 흐림으로, 평균 밝기가 상·하한을 벗어나면 과노출·저조도로 보고 `RETAKE`를 반환한다. 하한·상한 값은 평가셋으로 정한다.

### 4.2 1단계 전역 검색
- 기본 백본은 DINOv2 ViT-B/14(Apache-2.0)다. 패치 토큰에 GeM pooling(p=3)을 적용하고 L2 정규화한다.
- 합성 도형 장면으로는 전역 임베딩의 구분력을 검증할 수 없다(Task 4 실측: ViT-B/14에서 gem·mean·cls·cls_mean 모두 20쌍 중 8쌍 이하 승). 구분력은 실제 평가셋으로만 측정하고, 풀링(gem/mean/cls/cls_mean)은 비교 실험 축으로 둔다.
- 기준 갤러리에는 원본과 증강본(색상 변화, 무작위 crop, 좌우 반전 제외)을 넣는다.
- `s_g`는 갤러리와의 최대 코사인 유사도다.
- 백본은 교체할 수 있게 둔다. 비교 대상은 DINOv2-S/14, CLIP ViT-B/16, SigLIP이다.

### 4.3 2단계 기하 검증
- `s_g` 상위 k개(기본 3) 원본 기준 사진만 매칭한다. 유사도가 높은 순서로 하나씩 매칭하고, inlier가 `τ_n` 이상 나오면 나머지 쌍은 건너뛴다(4.4 조기 종료).
- 앱 기본값은 ALIKED(BSD-3) + LightGlue(Apache-2.0)다. 사용 전 각 저장소의 가중치 라이선스를 다시 확인한다. SuperPoint는 비상업 라이선스라 논문 비교 실험에만 쓴다. SIFT는 고전 기준선으로 둔다.
- `cv2.findFundamentalMat(..., cv2.USAC_MAGSAC)`로 inlier 수를 구하고, k개 중 최댓값을 `n`으로 둔다.
- 비슷한 외형의 다른 건물처럼 전역 유사도만으로 생기는 오판을 기하 일관성으로 걸러내는 것이 목적이다.

### 4.4 점수 결합과 판정
- 기본: 특징 `[s_g, log(1+n)]`에 로지스틱 회귀를 적용해 점수를 만들고, 거점별로 보정 fold에서 FAR 1%가 되는 지점을 임계값으로 정한다.
- 대체 규칙: 거점의 보정 데이터가 부족해 회귀가 불안정하면 `s_g ≥ τ_low AND n ≥ τ_n`을 쓴다.
- 임계값 파일은 `private/photo-verify/thresholds.json`에 둔다.

**조기 종료 (2026-10-12 확정)**
- 낮은 쪽 조기 거절(기본 켜짐): `s_g < τ_reject`이면 2단계 없이 `NO_MATCH`를 반환한다. `τ_reject`는 보정 fold의 정답 사진 중 이 값 아래로 떨어지는 비율이 1% 이하가 되도록 정한다.
- 통과는 항상 2단계를 거친다. 2단계가 비슷한 외형의 다른 대상을 걸러내는 역할을 하기 때문이다.
- 높은 쪽 조기 통과(기본 꺼짐): 거점별로 보정 fold의 모든 오답(어려운 오답 포함)보다 충분히 높은 `τ_accept`를 정할 수 있을 때만 그 거점에 켠다. 평가 fold에서 이 규칙으로 오답이 하나라도 통과하면 끈다.
- 적용 여부와 임계값은 `thresholds.json`에 거점별로 기록한다.

### 4.5 출력
```json
{"match": true, "score": 0.93, "reason_code": "MATCH", "latency_ms": 870}
```
- `reason_code`: `MATCH`, `NO_MATCH`, `RETAKE`
- 기준 사진 ID, 특징, 임계값은 응답에 넣지 않는다.

## 5. 구성 요소

신규 디렉터리 `photo-verify/`(Python 3.11)에 둔다. 웹 앱과 독립적으로 실행하고 시험한다.

| 경로 | 역할 | 의존 |
|---|---|---|
| `photo-verify/pv/preprocess.py` | EXIF 보정, 메타데이터 제거, 크기 조정, 품질 검사 | Pillow, OpenCV |
| `photo-verify/pv/global_embed.py` | 백본별 전역 임베딩 인터페이스(DINOv2 기본) | torch |
| `photo-verify/pv/local_match.py` | 특징점 추출·매칭·MAGSAC inlier 계산 | lightglue, OpenCV |
| `photo-verify/pv/gallery.py` | 거점별 기준 갤러리 생성(증강, 임베딩, 특징점 캐시)과 로드 | 위 두 모듈 |
| `photo-verify/pv/scorer.py` | 점수 결합, 임계값 로드, 최종 판정 | scikit-learn |
| `photo-verify/pv/service.py` | FastAPI `POST /verify?site_id=` (본문은 이미지 원시 바이트, multipart는 1MB를 넘으면 임시 파일에 쓰므로 쓰지 않음), `X-PV-Key` 헤더 인증, 파일 미저장, `GET /healthz` | FastAPI |
| `photo-verify/eval/run_eval.py` | 매니페스트 기반 평가, 비교 실험, 표·그림 출력 | scikit-learn, matplotlib |
| `photo-verify/tests/` | pytest 단위·계약 테스트 | pytest |

비공개 자료 위치(루트 `.gitignore`의 `/private/`로 이미 제외됨):

```
private/photo-verify/
  refs/<site_id>/*.jpg        기준 사진
  gallery/<site_id>.npz       갤러리 특징
  thresholds.json             거점별 임계값
  eval/manifest.csv           평가 매니페스트
  eval/images/...             평가 사진
```

## 6. 평가 프로토콜 (논문)

### 6.1 데이터
- 거점: 정문, 용봉관, 추모의 벽, 봉지
- 정답: 거점당 30~50장. 각도, 거리, 시간대(주간·저녁), 날씨, 사람 가림을 태그로 남긴다.
- 어려운 오답: 인접 건물, 다른 거점, 비슷한 표지석·조형물
- 쉬운 오답: 무관한 장소·사물 사진
- 기준 사진은 평가 사진과 다른 촬영 회차에서 고른다.
- 매니페스트 열: `path, site_id, label(pos/hard_neg/easy_neg), session, angle, distance, time, weather, occlusion`
- 촬영 시 사람 얼굴이 크게 나오지 않게 찍는다. 평가 사진은 저장소에 올리지 않는다.

### 6.2 분할과 지표
- 촬영 회차 기준 2-fold로 나눈다. 한쪽에서 임계값을 보정하고 다른 쪽에서 평가한 뒤 서로 바꾼다.
- 지표: ROC-AUC, EER, TAR@FAR=1%, 조건 태그별 TAR, 지연 p50/p95(CPU, 사양 기록)

### 6.3 비교 실험
| 축 | 비교 대상 |
|---|---|
| 구조 | (A) 전역만, (B) 국소만, (C) 결합 |
| 전역 백본 | DINOv2-S/14, DINOv2-B/14, CLIP ViT-B/16, SigLIP |
| 전역 풀링 | gem(clamp, p=3), mean, cls, cls_mean |
| 국소 매처 | SIFT+RANSAC, SuperPoint+LightGlue, ALIKED+LightGlue |
| 기준 사진 장수 | 1, 3, 5장 |
| 갤러리 증강 | 있음, 없음 |
| 조기 종료 | 항상 2단계, 낮은 쪽만 조기 거절, 양쪽 조기 종료. TAR@FAR=1%와 평균·p95 지연을 함께 비교 |
| 선택 기준선 | 비전 LLM 판정(논문 기여도와 호출 비용 문제로 앱 판정에는 쓰지 않음) |

## 7. 오류 처리

| 상황 | 처리 |
|---|---|
| 흐림·저조도·과노출 | `RETAKE` 반환. 시도 횟수에 넣지 않는다 |
| 알 수 없는 `site_id`, 갤러리 없음 | HTTP 404, 내부 정보 미포함 |
| 이미지 디코딩 실패, 크기 초과(기본 10MB) | HTTP 400 |
| 인증 실패 | HTTP 401 |
| 모델 오류·시간 초과 | HTTP 503. 앱 연동 단계에서 기존 관찰형 검증으로 대체한다 |
| 서버 준비 전 요청 | HTTP 503 NOT_READY |
| site_id 누락 | HTTP 422 (FastAPI 기본) |

## 8. 테스트

실제 현장 사진은 저장소에 넣지 않는다. 테스트는 합성 이미지로 한다.

- 같은 합성 장면에 회전·crop·밝기 변화를 준 쌍은 `MATCH`, 다른 장면은 `NO_MATCH`
- 흐린 이미지, 검은 이미지는 `RETAKE`
- EXIF 회전 보정과 메타데이터 제거
- API 계약: 응답 필드, 오류 코드, 인증
- 비저장: 요청 처리 후 작업 디렉터리·임시 디렉터리에 새 파일이 없는지 확인
- 모델 가중치가 필요한 테스트는 표식(`@pytest.mark.model`)으로 분리해 CI에서 선택 실행한다

## 10. 남은 결정

- 사진 판정을 쓸 거점과 단계, 실패 시 감점 정책(D5 연계)
- 운영 주체(장애 대응 담당)
- 사진 보관 허용 여부(D6). 정해지기 전까지 저장하지 않는다
- CPU 지연: 2단계 입력 640px 축소로 컨테이너 2vCPU p95 1.35초(최악 3쌍)까지 낮췄다. 남은 확인은 Cloud Run 실측·콜드 스타트, 그리고 평가셋에서 640px과 1024px의 TAR@FAR 비교다 (docs/LATENCY.md)

## 11. 추론 서버 배포 (2026-10-12 확정)

| 단계 | 배포처 | 설정 |
|---|---|---|
| 개발·논문 실험 | 로컬. 대량 비교 실험이 필요하면 Modal GPU | 평가 사진은 비공개 저장소 밖으로 올리지 않는다 |
| 운영 1순위 | Google Cloud Run `asia-northeast3`(서울) | CPU 2vCPU·4GB, min-instances 0, 요청 시간 제한 10초 |
| 운영 대체 | Modal GPU 서버리스 | CPU 실측 p95가 2초를 넘을 때 전환. 현재 이미지는 CPU 전용 torch라 같은 코드에 CUDA 휠을 쓰는 GPU 이미지 변형이 필요하고, Edge는 추론 서버 주소 비밀값만 바꾼다 |

- 하나의 코드베이스(FastAPI + PyTorch CPU 이미지, GPU 배포처는 CUDA 휠을 쓰는 변형 이미지)를 배포처에서 쓴다. 모델 가중치는 이미지에 넣고, 기준 갤러리와 임계값은 비밀 저장소나 비공개 버킷에서 시작 시 읽는다.
- 콜드 스타트는 게임 방을 만들 때 Edge가 `GET /healthz`를 호출해 미리 깨우는 방식으로 숨긴다. 행사 당일에는 min-instances를 1로 올릴 수 있다.
- 결제(2026-10-12 확정): 김동욱 개인 명의 GCP 결제 계정을 쓰고, 발생 비용은 나중에 청구해 정산한다. 정산 근거로 월별 청구 내역을 남긴다. 예산 알림(월 1만 원 기준 50·90·100%), max-instances=2, min-instances 기본 0을 설정한다. 예산 알림은 비용을 자동으로 막지 않으므로 알림을 받으면 직접 확인한다.
- Edge와 추론 서버 사이에는 공유 키 헤더로 인증한다. 키는 Supabase 비밀값과 Cloud Run 비밀값에만 둔다.
- 기각한 후보: Supabase Edge 내부 실행(CPU·메모리 제한), 외부 비전 AI API 운영 판정(논문 기여도와 호출 비용 문제, 비교 기준선으로만 사용), Hugging Face Spaces 운영(무료 티어 휴면, 가용성 보장 약함)
