# 정문 v2 확인용 UI

정식 디자인 작업 전에 합성 코스의 4인 흐름을 확인하기 위한 `/verify` 화면이다. 기존 색상·버튼과 인증·Realtime·재접속 처리를 재사용한다. 기존 `/` 화면은 v1이며 `/verify`는 v2 응답만 받는다. 이 화면 추가만으로 Supabase·Vercel에 배포되거나 활성 코스가 바뀌지 않는다.

## 로컬 실행

`web/`에서 의존성 설치 후 아래 PowerShell 명령을 사용한다. 로컬에서만 실행하며 생성한 salt를 출력하거나 공유하지 않는다. 매 실행의 코스 ID와 salt가 새로 생성되므로 **서버를 다시 시작하면 새 방으로 시험한다**. 실행 중 새로고침·재접속은 기존 방을 복구한다. 기존 코스 리비전을 덮어쓰지 않는다.

```powershell
$env:NEXT_PUBLIC_BACKEND = 'local'
$env:LOCAL_V2_COURSE_ID = 'jnu-demo-dev-ui-' + [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
$env:ANSWER_SALT = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
try {
  npm run dev -- --webpack --port 3012
} finally {
  Remove-Item Env:ANSWER_SALT, Env:LOCAL_V2_COURSE_ID -ErrorAction SilentlyContinue
}
```

브라우저에서 `http://localhost:3012/verify`를 연다. 기기 4대 또는 서로 다른 브라우저 프로필 4개가 필요하다. 같은 프로필의 탭 네 개로는 네 참가자가 되지 않는다. 실제 합성 답안은 이 문서·클라이언트에 제공하지 않는다. 답안을 몰라도 아래 힌트 3단계 경로로 완료 흐름을 확인할 수 있다.

## 확인 순서

1. 한 명이 호출명으로 새 방을 만들고, 나머지 세 명이 입장 코드로 합류한다.
2. 방장이 보직을 공개한다. 각자 준비 완료 후 지휘관이 출발한다.
3. 각자 **본인 모의 도착 확인**을 누른다. 모의 도착은 실제 위치 검증 기록이 아니다.
4. 본인 문제와 선행 조건을 확인한다. 입력 후 확인 방식으로 **합성 자료로 모의 확인**을 선택하고 합성 출처를 적어 제출한다. 문제 제출과 조사 결과 보고는 분리되어 있다.
5. 정찰원·통신원·암호해독관이 먼저 조사 결과를 보고한 뒤 지휘관 문제를 진행한다. 본인에게 공개된 숫자는 말로 전달한다.
6. 일반 경로에서는 지휘관이 전달받은 네 숫자를 입력해 자물쇠를 연다. 서버가 시도·감점·대기를 판정한다.
7. 해설 경로에서는 지휘관이 각 역할 힌트를 1→2→3 순서로 요청한다. 대상 역할의 미완료 문제가 해설 처리된다. 각자 보고하고 공개된 해설을 읽은 뒤 **내 해설 읽음 확인**을 누른다. 전원 보고·읽음 확인 후 지휘관이 **해설 확인 후 복원**을 누른다.
8. 완료 시 **정문 확인 완료** 화면을 유지한다. 다음 거점과 최종 결과는 이 확인 UI 범위가 아니다. 새로고침하여 진행·보고·자물쇠 상태가 복구되는지도 확인한다.

## 개인정보와 복구

- 지휘관 전달형 단서는 지휘관의 자기 화면에만, 힌트·해설·보상·기록은 서버가 허용한 자기 응답에만 표시한다. 전체 응답이나 답안을 콘솔에 출력하지 않는다.
- v2 답안·출처·자물쇠 입력은 메모리에만 두며 브라우저 저장소에는 게임 ID만 보관한다. Supabase의 기존 익명 인증 세션 저장은 유지한다.
- 응답 유실 시 **다시 연결**로 같은 본문·같은 request_id를 재전송한다. 응답이 불명확한 동안 다른 쓰기 요청은 막는다. 페이지를 새로고침하면 서버 상태만 복구하고 미확정 요청·입력 초안은 복구하지 않는다. 먼저 진행 상태를 확인한 뒤 필요한 동작만 다시 수행한다.
- `get-game`으로 로비·이동 상태를 확인하고, 정문 도착 후에는 `get-stage`를 조회한다. 낮은 version의 응답은 적용하지 않는다.
- 완료 직후 개방 주체의 화면에는 서버 result.label을 표시한다. 재접속 응답에는 개방 방식이 없으므로 재접속 후에는 정문 완료 사실만 표시하고 방식을 추측하지 않는다.

## dev 연결과 검증

Supabase에서 시험하려면 [PR-2 적용 안내](../be/PR_2_APPLY.md)에 따라 사용자가 새 마이그레이션·Edge·새 v2 합성 코스를 준비한다. 이 확인 화면을 포함해 Vercel을 재배포한 뒤 `/verify`를 사용한다. 공개 환경변수는 기존 3개이며 새로운 비밀값은 필요 없다. 활성 코스를 v2로 바꾸면 **새 방은 `/verify`에서 생성**한다. 기존 r1 방은 기존 `/`에서 이어갈 수 있다.

```powershell
npm run typecheck
npm test
npm run test:e2e:v2
```

v2 브라우저 시험은 새 로컬 서버·임의 salt·새 리비전·독립 세션 네 개를 사용한다. API·개인 단서가 들어가는 trace·영상·스크린샷·실패 페이지 덤프를 보관하지 않는다. 기존 v1 회귀는 v2 선택 환경변수를 해제하고 별도로 `npm run test:e2e`를 실행한다. 실제 Supabase·휴대폰·현장 GPS 시험과 구분한다.

정식 FE는 이 화면의 디자인을 따를 필요 없이 [API 계약](../be/API_CONTRACT.md)과 [mock 12개](../be/API_CONTRACT.md#31-fe용-전체-snapshot-mock)를 기준으로 작업하면 된다. 서버 시나리오·판정·PR-3 이후 범위는 이번 UI에서 변경하지 않는다.

## 실행한 검증 (2026-10-08, 로컬 합성 코스)

- 단위·DB·계약 94개 통과, TypeScript 검사·production 빌드 통과.
- 새 v2 브라우저 시험 2개 통과: 각각 독립 세션 네 개로 정상/해설 개방, 개인 자료 격리, 별도 보고, 부분 잠금과 재접속, 응답 유실 뒤 동일 request_id·감점 1회를 확인했다.
- 기존 v1 브라우저·API 회귀 9개 통과. 공통 상태 훅 변경 후 기존 두 거점 완주·새로고침·입력 초안 복구를 재검증했다.
- Deno lint로 신규/변경 UI·통신·v2 테스트 9개 파일 검사 통과. Next의 확장자 생략 import와 브라우저 window 관련 규칙만 제외했다. 저장소에 npm lint 스크립트는 없다.
- Windows에서 Turbopack CSS 하위 프로세스 생성 오류가 제한 밖에서도 반복되어 브라우저 시험 서버를 Webpack으로 실행했다. 첫 UI 시험에서 입력 라벨과 오류 알림 선택자를 보완한 뒤 통과했다.
- Supabase/Vercel 배포·실제 휴대폰 네 대·현장 GPS 검증은 수행하지 않았다.
