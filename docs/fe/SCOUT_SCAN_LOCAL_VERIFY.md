# 정찰원 '사진으로 찾기' — 로컬 실제 판정 연결 (개발 전용)

개발 서버의 정찰원 '사진으로 찾기'에서 모의 판정 대신 로컬 사진 판정 서버(`photo-verify`)가 실제로 판정한다. 엔진·Edge·운영 빌드는 바꾸지 않는다. 실패 횟수는 지금처럼 그 기기에만 남는다(정식 연결은 이슈 #20과 BE 작업).

## 흐름

카메라 촬영(긴 변 1600px JPEG) → `POST /api/dev/photo-verify?site_id=gate`(개발 서버 전용, 운영 빌드는 404) → 판정 서버 `/verify` → 결과

| 판정 서버 응답 | 화면 | 실패 횟수 |
|---|---|---|
| `match: true` | 사진으로 찾음 → 문제 열림 | — |
| `NO_MATCH` | 조금 달라요 + 힌트 | +1 |
| `RETAKE`, 400(사진 읽기 실패) | 어둡거나 흔들려 확인 못 함, 가까이에서 다시 | 세지 않음 |
| 503·연결 실패 | 같은 사진으로 다시 확인 | 세지 않음 |

판정 서버 주소와 키는 Next 서버 환경변수에만 두고 브라우저에는 보내지 않는다. 사진은 넘기기만 하고 저장하지 않는다.

## 실행

1. 판정 자료 준비(비공개, 커밋 금지): `thresholds.json`과 `gallery/gate.npz`가 있는 폴더. 기준 사진·기준값은 정답 자료라 저장소에 없다. 김동욱에게 받는다.
2. 판정 서버 (`photo-verify`)
   ```powershell
   $env:PV_API_KEY = '<임의의 긴 문자열>'; $env:PV_DATA_DIR = '<판정 자료 폴더>'
   uv run uvicorn pv.service:app_from_env --factory --host 127.0.0.1 --port 8077
   ```
3. `web/.env.local` (git 제외)
   ```
   PV_URL=http://127.0.0.1:8077
   PV_API_KEY=<2와 같은 값>
   NEXT_PUBLIC_PHOTO_VERIFY=local
   ```
4. 개발 서버를 띄우고 혼자 데모 체험 → 정문 도착 → 정찰원. 폰 카메라는 https에서만 열리므로 폰 시험은 `npm run dev -- --webpack --experimental-https --hostname 0.0.0.0`으로 띄우고 같은 와이파이에서 `https://<PC IP>:3000`으로 연다(자체 서명 인증서 경고는 시험 기기에서만 허용).

`NEXT_PUBLIC_PHOTO_VERIFY`를 비우면 예전처럼 모의 판정(맞게/다르게/다시 찍기/연결 오류)을 쓴다.

## 확인 (2026-10-30)

- 단위 시험: 다시 찍기는 실패로 세지 않음, 판정은 새 요청에만 한 번, 장애 뒤 같은 요청 재시도, 응답 대응·키 비노출
- 브라우저: 가짜 카메라에 실제 정문 사진을 재생해 정답 → '사진으로 찾음', 근처 석조물 → '실패 1 / 3'
- 기준값은 10/27 밤 사진으로 정한 **임시값**이다. 오답 평가 전이라 오인식률은 모른다. 실제 폰·현장 시험은 하지 않았다.
