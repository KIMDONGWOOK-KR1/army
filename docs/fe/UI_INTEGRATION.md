# 메인 UI와 정문 v2 연결

기존 v1 정문 문항을 임시 v2 코스로 확인하려면 [v1 정문 dev 이관 안내](../be/LEGACY_GATE_DEV.md)를 따른다. 기존 통합 UI에서 동작하며 기본 합성 시험 코스와 별도 리비전으로 등록한다.

2026-10-09 · `feat/ui-v2-integration`

PR #8의 메인 디자인과 PR #9의 정문 v2 API를 연결하는 브랜치다. 기준은 PR #8 `14c105f`와 PR #9 `8441e76`이며 두 PR의 변경을 함께 포함한다. PR #8의 3D 첫 화면·로비·보직 공개·장비·이동·폰 목업은 유지하고, `/`에서 서버가 반환한 코스 버전에 맞는 미션을 표시한다. `/verify`도 계속 사용할 수 있다.

이 문서는 코드 연결 안내다. Supabase 마이그레이션·Edge·코스 등록·Vercel 배포 또는 실제 네 기기 시험이 완료되었다는 뜻은 아니다.

## 연결한 흐름

1. 네 명이 각각 방 생성·코드 합류 → 보직 공개 → 준비 → 지휘관 출발을 진행한다.
2. dev 합성 v2 방에서는 **각자 본인 모의 도착 확인**을 누른다. 정문 기본 조건은 전원 도착이다. 실제 GPS 검증이나 다른 역할 도착 대행으로 취급하지 않는다.
3. 본인 미션의 문제별 상태·입력·확인 방식·출처·해설을 표시한다. 미완료 선행 조건이 있으면 해당 문제 입력이 잠긴다.
4. 문제 제출과 **조사 결과 보고**를 분리한다. 보고 후 본인 숫자를 표시하고 지휘관에게 말로 전달하도록 안내한다. 지휘관 전달형 단서는 지휘관 화면에만 나온다.
5. 지휘관은 역할별 1→2→3단계 힌트를 요청한다. 본문은 해당 역할에만 공개한다. 3단계는 해당 역할의 미완료 문제 전체를 해설 처리한다.
6. 지휘관의 **팀 자물쇠로** 화면에 일반 자물쇠와 **해설 확인 후 복원**을 별도로 둔다. 후자는 네 명의 보고·해설 읽음 확인 뒤에만 실행된다. 일반 자물쇠의 시도·감점·대기는 서버 규칙을 따른다.
7. 정문 완료 화면에 머문다. 후속 거점·PR-3 액션을 호출하지 않는다.

## FE가 사용할 코드

| 파일 | 역할 |
|---|---|
| [game-app.tsx](../../web/components/game-app.tsx) | 기존 장면을 유지하며 v1/v2 미션·도착·완료 흐름 분기 |
| [mission-v2.tsx](../../web/components/mission-v2.tsx) | 역할별 문제·보고·힌트·읽음 확인과 별도 자물쇠 화면 |
| [legacy-mission-input.tsx](../../web/components/legacy-mission-input.tsx) | dev `v1-gate`의 기존 선택 버튼·관찰 입력·무전기·달력 표시. 판정과 보고는 v2 사용 |
| [verify-input.tsx](../../web/components/verify-input.tsx) | 두 UI가 공유하는 타입별 입력. 주파수는 한 자리 이하 소수 문자열 |
| [use-game.ts](../../web/components/use-game.ts) | 메인 `useGameAny`, 확인 UI `useGameV2`, 기존 `useGame`. 상태 재조회·Realtime·재시도 |
| [client.ts](../../web/lib/client.ts), [game-snapshot.ts](../../web/lib/game-snapshot.ts) | 인증·HTTP 공통 전송과 실제 응답의 버전 판별 |

`game.demo`만으로 v1 혼자 체험 기능을 켜지 않는다. v2 합성 코스도 `demo:true`지만 네 참가자 각각의 동작이 필요하다. v1 자동 시연·보직 전환은 v1에서만 유지한다.

기존 UI 재사용은 `course.demo`인 정문의 역할별 `G-01.legacy`~`G-04.legacy` ID·유형·채점 방식이 맞을 때만 적용한다. 다른 v2 문항과 `/verify`는 일반 입력을 유지한다. 달력은 기존 공개 표시 컴포넌트를 공유하고 답은 선택 번호로 전송한다. 무전기는 v2에서 직접 입력을 반올림하지 않으며 제출 대기·잠긴 상태에는 다이얼의 포인터·휠·키보드 조작도 막는다. UI 적용에는 웹 재배포만 필요하며 기존 코스 등록과 Edge 배포를 반복하지 않는다.

달력은 기존 v1 문제에 맞춘 고정 표시다. 해당 문제의 날짜를 수정할 때는 `mission-calendar.tsx`도 함께 확인한다.

답안·개인 단서·숫자를 새 브라우저 저장 항목이나 로그로 복사하지 않는다. v2 미확인 요청은 메모리에만 보관하고 응답 유실 재시도에는 동일 `request_id`와 본문을 사용한다. 새로고침 뒤에는 서버 상태를 조회한다. 입력 중인 답안·잠기지 않은 자물쇠 초안은 다시 입력해야 한다. 폰 목업 전환에서도 이 원칙을 지킨다. 기존 익명 인증과 게임 ID·보기 설정은 계속 저장한다.

최초 방 생성·합류 응답까지 유실되면 같은 화면의 **다시 연결**로 복구한다. 방 ID를 한 번도 받지 못한 상태에서 새로고침하면 Supabase에서 방을 자동 복구할 ID가 없으므로 입장 코드로 합류해야 한다. 완료 방식 문구는 지휘관의 개방 응답을 메모리에 유지한다. 새로고침·다른 참가자 조회에는 현재 API가 완료 방식을 제공하지 않아 일반 정문 완료 문구를 표시한다.

## 실행과 dev 연결

- 기본 `npm run dev`는 v1 로컬 데모다. 로컬 v2는 [PR-2 로컬 API 개발](../be/PR_2_APPLY.md#로컬-api-개발)에 따라 로컬 전용 무작위 salt와 새 합성 리비전을 설정한 뒤 `/`를 연다. Edge salt를 복사하지 않는다.
- 자동 v2 UI 시험은 `web/`에서 `npm run test:e2e:integration`으로 실행한다. 포트 3014의 로컬 서버, 실행마다 새 리비전·무작위 salt, 독립 브라우저 세션 네 개를 사용한다. 클라우드와 연결하지 않고 개인 응답이 포함된 trace·화면 캡처를 저장하지 않는다.
- Supabase dev 연결은 [PR-2 적용 절차](../be/PR_2_APPLY.md)를 사용자가 수행한다. 이미 적용한 항목은 먼저 확인한다. UI 연결 자체로 추가되는 마이그레이션·Edge 비밀값·공개 환경변수는 없다.
- PR-2 DB·Edge·새 v2 합성 코스가 준비되면 기존 공개 환경변수 세 개로 이 브랜치의 웹을 배포하고 **새 방**을 만든다. 기존 v1 방은 기존 코스를 유지한다. 별도 origin에서 시험하면 정확한 origin을 Edge 허용 목록에 추가한다.
- 사용자의 Vercel 저장소 루트 배포·Root Directory=`web` 구성을 유지한다. 새 UI 런타임 파일은 모두 `web/` 안에 있다. 기존 코스 검사·seed의 저장소 루트 참조는 그대로다.

비밀값 입력과 Supabase/Vercel 적용은 사용자가 한다. 배포용 로컬 파일·실제 시나리오·GPS 원본을 커밋하지 않는다.

## 검증 범위와 남은 항목

`tests/e2e/integrated-v2.spec.ts`는 실제 `/`에서 네 역할의 정상 자물쇠·해설 개방, 역할별 정보 격리, 문제와 보고 분리, 잠긴 칸 복원, 응답 유실 재시도와 중복 감점 방지, 브라우저 저장소·콘솔 노출을 검사한다. `integrated-v2-layout.spec.ts`는 공개 mock으로 네 역할의 360·390·430px 배치와 목업 전환 시 미제출 숫자 저장 금지를 확인한다. 실행 결과는 [검증 기록](../../web/docs/VALIDATION.md)에 기록한다. `/verify` 회귀와 기존 v1 E2E는 별도로 실행한다.

실제 Supabase private Realtime·Vercel 배포·iOS/Android 실기기·현장 GPS 검증은 배포 후 필요하다. 실제 시나리오 미확정 사항과 점수·랭킹 결정 대기는 [DECISIONS.md](../be/DECISIONS.md)를 따른다. API와 합성 mock은 [API_CONTRACT.md](../be/API_CONTRACT.md)를 기준으로 사용한다.
