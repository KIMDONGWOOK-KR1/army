# 정문 v2 UI 복원 안내

2026-10-09 · `feat/ui-v2-integration`

기존 UI에서 빠졌던 장면을 정문 v2 서버 상태에 연결했다. 후속 거점 엔진이나 운영 시나리오 완성을 뜻하지 않는다. 기존 무전기·달력·선택 문제 연결은 [통합 안내](UI_INTEGRATION.md)를 참고한다.

| 연결한 화면 | 동작 |
|---|---|
| 숫자 획득 | 문제 제출 후 별도 보고를 마치면 본인 숫자 화면으로 이동한다. 다른 역할의 숫자는 받지 않는다. |
| 조사·해설 돌아가기 | 숫자·대기·자물쇠 화면에서 본인 조사로 돌아가고 다시 숫자·자물쇠 화면을 열 수 있다. |
| 자물쇠 입력 | 같은 화면 세션에서 이동하는 동안 초안을 메모리로 유지한다. 새로고침·목업 전환 때 초안은 저장하지 않는다. 서버가 잠근 칸만 복구한다. |
| 사초와 기록첩 | 완료된 공개 사초 본문·도장과 본인의 검증 결과·기록·출처·해설을 표시한다. 타 역할의 개인 기록은 제공하지 않는다. |
| 정문 결과 | 사초에서 결과 화면과 기록첩을 열 수 있다. 전체 코스 종료로 처리하거나 다음 거점으로 출발하지 않는다. |
| 완료 방식 | `해설 확인 후 복원` 표시를 서버에서 조회해 다른 참가자·새로고침에도 유지한다. |
| 기존 연출 | `v1-gate` dev 코스에서 기존 시작·도착·사초 나레이션과 거점 도착 화면을 재사용한다. |

## 로컬 시연과 4인 방

사용자 결정에 따라 자동 시연·보직 전환·장면 건너뛰기는 **로컬 dev의 별도 v1 혼자 체험 방**에서 사용한다. `LOCAL_V2_COURSE_ID`를 설정해도 첫 화면의 **혼자 데모 체험**은 기존 v1 시연을 만든다. **작전 시작 → 새 작전 만들기**는 설정된 v2 코스를 사용한다.

v2 방은 네 참가자의 준비·도착·보고·해설 확인을 계속 요구한다. Supabase/배포 환경에서 로컬 시연 API는 사용할 수 없다. v1 자동 시연의 두 거점 진행을 v2 후속 거점 구현으로 해석하지 않는다.

## API 추가와 적용

- `game.completion`: 현재 단계 완료 시각·방식·표시 문구. 완료 전에는 `null`이다.
- `self.journal`: 완료된 단계 중 인증된 본인 역할의 기록만 반환한다. 답안 배열·해시·숫자·전달 단서는 넣지 않는다.
- 완료된 장소의 `sacho.char`, `sacho.body`: 선택형 공개 보상 필드다. 완료 전에는 공개하지 않는다. 사용자 개인 기록과 구분한다.

정확한 형식과 합성 mock은 [API 계약](../be/API_CONTRACT.md)에 있다. 이전 Edge 응답에는 기록첩이 현재 해설을 대신 표시하며, 완료 방식의 재조회에는 새 Edge가 필요하다.

**새 마이그레이션·비밀값은 없다.** DB CAS·`request_id` 멱등성·기존 감점과 시도 규칙을 유지한다. 사용자가 통합 브랜치의 `web/`에서 다음 순서로 적용한다.

1. 기존 `ANSWER_SALT`를 그대로 사용한다. 기존 `v1-gate` 코스에 사초 본문·도장이 없다면 [dev 코스 안내](../be/LEGACY_GATE_DEV.md)에 따라 **새 리비전**으로 등록한다. 예시는 `jnu-demo-dev-v1gate-r2`이며 이미 사용한 ID는 재사용하지 않는다. 키·salt는 사용자가 직접 마스킹 입력한다.
2. 새 코스를 등록했다면 `ACTIVE_COURSE_ID`를 전환한다. 기존 방은 원래 코스를 유지한다.
3. 이 브랜치의 Edge `game`을 다시 배포한다.

```powershell
npx.cmd supabase functions deploy game --project-ref <DEV_PROJECT_REF>
```

4. 기존 Vercel 프로젝트·Root Directory=`web` 구성으로 웹을 배포한다. 새 공개 환경변수는 없다. 새 방에서 네 세션을 확인한다.

변환 코드는 seed에서만 실행한다. 새 웹 런타임 파일은 모두 `web/` 안에 있다. 합성 코스는 dev 전용이며 prod 허용 설정을 추가하지 않는다. 코드 검증 결과는 [검증 기록](../../web/docs/VALIDATION.md)에 별도로 기록한다. 이번 작업은 Supabase/Vercel 적용 완료를 의미하지 않는다.

## 확인할 흐름

네 명 입장·준비·도착 → 본인 문제 제출 → 별도 보고 → 숫자 획득 → 조사·해설로 왕복 → 지휘관 자물쇠 → 사초 → 정문 결과 → 수집한 기록을 확인한다. 별도 방에서는 역할별 3단계 힌트 → 전원 보고·읽음 확인 → 지휘관 별도 개방 → 새로고침 후 완료 방식 유지도 확인한다.

후속 거점 이동·역할 교환·봉지·추모의 벽 공동 기록·전체 코스 결과·랭킹은 해당 후속 PR 범위다. 이 화면 복원으로 구현된 것으로 표시하지 않는다.
