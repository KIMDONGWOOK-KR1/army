# 정문 정찰원 사진 미션 — UI 담당자 전달 문서

작성일: 2026-10-23 · 브랜치: `feat/scout-photo-gate` · 시작 기준: `main`의 `e1a58e7`

## 이번에 전달하는 것

정찰원 G-02를 **개인 상징 단서 → 직접 촬영 → 사진 판정 → 객관식**으로 바꾸기 위한 개발용 화면과 mock 연결 틀이다. UI 담당자는 이 흐름을 실제 게임의 디자인에 맞게 다듬으면 된다.

**현재는 독립된 로컬 미리보기다. 사진 모델·실제 업로드 API·DB·실제 게임의 진행 상태와 연결되지 않는다.** 사진 판정과 객관식 채점은 개발자가 선택한 모의 결과를 사용한다. 실제 정문 문제, 점수, 보고, 자물쇠, 배포된 코스는 바뀌지 않는다.

이 브랜치는 배포용 `feat/gate-tribute-ui`가 아니라 위 `main`에서 시작했다. 다른 브랜치의 최신 UI 변경이 모두 포함됐다고 가정하거나 메인 게임 파일 전체를 덮어쓰지 않는다.

## 실행 방법

이 브랜치의 저장소에서 실행한다. 패키지를 아직 설치하지 않았다면 `web/`에서 먼저 `npm ci`를 실행한다.

```powershell
cd web
npm run dev -- --webpack --port 3016
```

접속 주소: <http://localhost:3016/dev/scout-photo>

공유 미리보기: <https://mino-scout-photo-preview.vercel.app/>. 로그인 없이 확인할 수 있는 별도 합성 mock 복사본이며, `카메라 없이 시연`과 UI 전달 안내 다운로드를 제공한다. 실제 게임·모델·Supabase에 연결되지 않으며 이 브랜치와 자동으로 동기화되지 않는다. 아래 개발 전용 경로의 운영 차단은 그대로 유지한다.

- `NODE_ENV=development`에서만 열리는 경로다. 운영 빌드에서는 공개하지 않는다.
- Supabase 로그인·방 생성·코스 등록·GPS 현장 도착·모델 API 키가 필요 없다.
- 이 경로는 혼자 UI를 확인하는 개발 도구이며 4인 게임의 역할 인증을 대신하지 않는다.
- 개발 도구의 역할 선택을 바꾸면 정찰원 외 화면에서 개인 단서가 숨겨지는 모습을 확인할 수 있다. 실제 서버 권한 검증은 아직 연결하지 않았다.
- 로컬 컴퓨터의 `localhost`는 카메라를 사용할 수 있다. 휴대폰에서 PC의 일반 HTTP LAN 주소로 접속하면 카메라가 차단될 수 있다. 휴대폰 촬영 시험에는 HTTPS 개발 환경과 카메라 권한이 필요하다.
- 개발 환경의 `/dev/scout-photo`에만 `Permissions-Policy: camera=(self), microphone=(), geolocation=()` 예외를 적용했다. 기존 게임 경로와 운영 환경의 카메라 차단 정책은 유지한다. 실제 게임에 통합할 때는 대상 경로의 카메라 허용 정책도 함께 준비해야 한다.

## 화면 순서와 상태

| 화면·상태 | 보여줄 내용과 동작 |
|---|---|
| 개인 단서 | 정찰원용 상징 스티커와 이를 암시하는 짧은 퀴즈형 문장. 현재 그림·문장은 합성 placeholder이며 실제 조형물 사진을 보여주지 않는다. |
| 촬영 | 사용자가 버튼을 누르면 카메라 권한을 요청한다. 조형물 중심으로 촬영하고 사람 얼굴 등을 피하도록 안내한다. |
| 미리보기 | 촬영한 사진을 확인하고 재촬영하거나 제출한다. 출처·확인 방식·작품 이름 입력칸은 없다. |
| 판정 중 | 중복 제출을 막고 진행 상태를 알린다. 실제 모델 성능이나 통과율을 표시하지 않는다. |
| 검증 성공 | 사진 단계 완료 후 코스 데이터의 객관식 문항으로 이동한다. |
| 검증 실패 1~2회 | 실패 횟수를 표시하고 다시 촬영할 수 있다. |
| 검증 실패 3회 | 사진 단계만 자동 통과한다. **`사진 검증 실패 후 통과`**라고 표시하며 검증 성공으로 꾸미지 않는다. 객관식은 계속 풀어야 한다. |
| 촬영 불가 | 카메라 오류·권한 거부·촬영 금지 등으로 사진을 못 찍는 경우의 경로다. mock에서는 같은 3회 규칙을 보여준다. |
| 서버 오류 | 오류를 안내하고 재시도할 수 있다. 검증 실패 횟수를 늘리거나 감점하지 않는다. |
| 객관식 | 문항·선택지·문항 수를 데이터로 받는다. 모의 채점이 거절이면 같은 문항에 머무르고, 수락이면 다음 문항으로 이동한다. |
| 미션 완료 시연 | 사진 판정 완료 이유와 객관식 진행 결과를 확인한다. 실제 서버에 보고하거나 숫자·점수를 저장하지 않는다. |

일반 사진 실패와 자동 통과를 서로 다른 상태로 표현한다. 실패 후 자동 통과한 결과에는 `verified: false`를 유지한다. 객관식 완료가 사진 검증 성공을 뒤늦게 만들어 주는 것도 아니다.

## UI 담당자가 유지할 규칙

- 정찰원 본인의 개인 단서만 보여준다. 실제 연결 시 다른 역할의 응답이나 팀 공용 상태에 이미지·개인 문장을 복사하지 않는다.
- 사진 검증용 기준 사진과 상징 스티커는 별개다. 기준 사진·임베딩·유사도·임계값은 FE에 내려주지 않는다.
- 실제 작품 이름 직접 입력, observation 출처 기록, 확인 방식, 근거 연결 양식은 이 새 화면에 넣지 않는다. 작품 이름을 묻는 경우도 향후 객관식 콘텐츠 안에서 구성한다.
- 사진 단계와 객관식 단계를 구분한다. 사진 실패 3회가 객관식·정찰원 보고·정문 자물쇠까지 완료시키면 안 된다.
- D5 감점은 `null`, `confirmed: false`, `TODO(확인필요)` 상태다. mock에서 점수를 차감하지 않는 것이 운영 감점 0점 확정이라는 뜻은 아니다. 임계값도 미확정이며 BE 비공개 설정이므로 UI fixture나 응답 필드에 추가하지 않는다.
- 역할 3단계 힌트와 새 사진 단계의 관계는 후속 결정 사항이다. 이번 미리보기에 새 힌트 우회 규칙을 만들지 않는다.
- 모바일 폭 360~430px, 터치 영역 44px 이상을 기준으로 한다. 문장은 자동 줄바꿈하고, 가로 스크롤·고정 높이 때문에 긴 문구가 잘리지 않게 한다.
- 카메라 화면을 벗어나면 스트림을 종료한다. 미리보기 교체·초기화·화면 종료 때 사진 URL과 참조를 해제한다.

## 개발용 결과 선택

모델이 없어도 화면 전체를 확인하도록 개발 도구에서 다음 결과를 선택한다.

| 대상 | 모의 결과 | 확인할 장면 |
|---|---|---|
| 사진 | `match` | 사진 성공 → 객관식 |
| 사진 | `no_match` | 재촬영, 실패 3회 후 자동 통과 |
| 사진 | `service_error` | 장애 안내, 실패 횟수 유지 |
| 객관식 | 수락 / 거절 | 다음 문항 이동 / 오답 상태 유지 |

**선택지에 숨은 정답을 붙여 FE에서 채점하지 않는다.** mock은 개발자가 지정한 수락·거절 결과를 반환한다. 합성 fixture를 실제 답안이나 운영 코스 시드로 사용하지 않는다.

mock 상태는 브라우저 메모리에서만 유지한다. 새로고침으로 초기화되는 것은 개발 도구의 한계이며, 실제 게임의 재접속 동작으로 구현하면 안 된다.

```text
사진·객관식 UI
    ↓ 계약 타입에 맞춘 어댑터
현재: 로컬 mock → 모의 상태 반환
향후: 인증된 BE → 사진 모델 → 서버 판정·게임 커밋 → 상태 반환
```

### 어댑터 사용 예시

아래는 HTTP 요청이 아니라 브라우저 안에서 실행하는 개발용 호출이다. `capturedBlob`은 촬영 도우미로 만든 사진이다.

```ts
import { createMockPhotoGateClient } from "@/lib/scout-photo/mock";
import { scoutPhotoMission } from "@/lib/scout-photo/fixture";

const client = createMockPhotoGateClient({ mission: scoutPhotoMission });
client.setPhotoOutcome("no_match");
client.setChoiceOutcome("accepted");

const reply = await client.submitPhoto({
  requestId: crypto.randomUUID(),
  stepId: scoutPhotoMission.photoStep.id,
  photo: capturedBlob,
});
// reply.source === "mock"
// reply.state.photo.status: pending | verified | failed_pass
// reply.state.photo.failureCount: 검증 실패 횟수
// reply.result.kind: photo_retry | photo_failed_pass 등
```

| 메서드 | 입력·결과 |
|---|---|
| `getState()` | 현재 mock 상태 조회 |
| `submitPhoto({ requestId, stepId, photo })` | Blob을 받아 선택한 모의 결과 반환. 네트워크 전송 없음 |
| `reportUnavailable({ requestId, stepId, reason })` | `camera_unavailable` 또는 `photography_prohibited` |
| `submitChoice({ requestId, stepId, answer })` | 선택 번호 문자열(`"1"`부터). 모의 수락·거절 반환 |

`PhotoGateReply`는 `source`, `requestId`, `state`, `result`로 구성된다. `state.choiceProgress`는 문항별 완료 여부이고 `state.completed`는 미리보기의 전체 완료 여부다. 유사도·임계값·임베딩은 응답 필드에 없다.

`source: "server"`는 향후 연결을 위한 예약 타입이며 현재 구현은 항상 `"mock"`을 반환한다. 현재 타입에 서버 주소만 연결하는 것으로 실제 인증·판정이 준비되지는 않는다. 이 프로토타입의 `requestId`와 `stepId`는 FE 어댑터용 이름이며 기존 게임 HTTP 계약의 `request_id`·`step_id`와 자동으로 호환되지 않는다.

## 사진·개인정보

이번 미리보기는 사진을 서버나 외부 모델로 업로드하지 않는다. 브라우저 메모리에서만 미리보고, 사진을 localStorage·IndexedDB·분석 로그·게임 이벤트에 기록하지 않는다. 직접 촬영 UI는 사용 편의를 위한 흐름이며 다른 화면이나 인쇄물을 찍지 않았다는 보안 증명이 아니다.

현재 촬영 도우미는 영상 프레임을 캔버스에서 JPEG로 새로 만들고 긴 변 1,600px·2MiB 이내로 준비한다. 원본 파일·EXIF를 읽어 전송하는 구조가 아니다. 이 값은 미리보기 기본값이며 실제 업로드 정책 확정을 뜻하지 않는다.

실제 API 연결 시에는 제출 전에 이미지 리사이즈·재인코딩으로 EXIF와 원시 GPS를 제거하고, 서버가 형식·용량·디코딩을 다시 검증해야 한다. 서버 인증키·모델 키·기준 사진은 FE 환경변수나 저장소에 넣지 않는다.

실제 연결 후 안내 문구 초안은 아래와 같다. 실제 서버·모델의 처리 방식과 맞춘 뒤 사용한다.

> 조형물만 촬영해 주세요. 다른 사람의 얼굴·명찰·차량번호가 나오지 않도록 주의해 주세요. 사진은 검증을 위해 일시 전송되며 처리 후 보관하지 않습니다. 유사도와 판정 결과만 저장합니다. 촬영이 금지된 장소이거나 카메라를 사용할 수 없다면 ‘촬영 불가’를 선택해 주세요.

현재 mock 화면에는 대신 **사진을 전송하지 않는 개발용 미리보기**임을 표시한다.

## UI 인수 체크리스트

- [ ] 개인 상징 단서부터 사진·객관식까지 한 흐름으로 확인한다.
- [ ] 성공, 실패 1~2회, 실패 3회 자동 통과, 촬영 불가, 서버 오류를 모두 표시한다.
- [ ] 자동 통과 문구는 `사진 검증 실패 후 통과`이며 검증 성공 표시가 없다.
- [ ] 사진이 자동 통과해도 객관식은 남아 있다.
- [ ] 객관식이 여러 개일 때 문항 수·순서가 데이터에 따라 바뀐다.
- [ ] 출처·확인 방식·이름 입력 UI와 숨겨진 정답 채점이 없다.
- [ ] 카메라 권한 거부·사용 불가·다시 촬영·화면 종료를 처리한다.
- [ ] 휴대폰에서 사진·문구·버튼이 잘리지 않고 키보드·스크린리더도 사용할 수 있다.
- [ ] 사진·전체 응답·개인 단서를 콘솔이나 분석 로그로 보내지 않는다.
- [ ] 실제 Supabase 방·점수·진행에 모의 결과가 저장되지 않는다.

위 목록은 인수 기준이다. 체크되지 않은 항목을 실기기 검증 완료로 해석하지 않는다. 이번 전달에는 모델 배포, 실제 사진 정확도 검증, Supabase 변경, 새 코스 등록, Vercel 배포가 포함되지 않는다.
