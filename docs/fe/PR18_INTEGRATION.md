# PR #18 FE 통합 기준

2026-10-27 · `feat/gate-tribute-ui`에서 PR #18 `82a86c8`을 통합한다. 이 문서는 코드의 통합 기준이며 GitHub 병합이나 클라우드 배포 완료를 뜻하지 않는다.

## 사용자 확정 사항

- 현재 BE 채점·도착·보고·자물쇠·헌화 완료 조건을 유지한다. 마이그레이션이나 Edge 액션 변경은 없다.
- 정문 기존 문제 UI와 공통 → 본인 역할 개인 나레이션을 유지한다. FE의 나레이션 스크롤·한 번에 읽기·화면 디자인을 결합한다.
- `확인 방식`·`확인한 출처`·`연결할 자료` 공통 입력을 복원하지 않는다. 봉지 공동 문장 자동 조합도 유지한다.
- 첫 화면 복귀·재접속 처리와 429 대기·동일 request_id 재시도 수정을 유지한다.
- 점수·힌트 감점·자물쇠 감점 안내를 유지한다. 기존 추모 화면의 점수 숨김은 그대로다.
- 추모의 벽은 전원 도착 → 묵념 연출 → 각자 국화 한 송이로 이어진다. 자연음·묵념 음악을 적용하며 사용자 소리 설정을 따른다. 묵념 연출은 서버의 추가 완료 조건이 아니다.
- 문제 화면 지도, 출발 버튼 배치, 팀 진행 표시와 네 거점 혼자 시연을 적용한다.

## 사진 찾기의 현재 한계

실제 이미지 임베딩·사진 업로드·서버 실패 횟수 저장은 연결하지 않았다. 사진 찾기는 `NODE_ENV=development`, 로컬 backend, 모의 도착 가능한 demo 코스의 정찰원에게만 연결한다. Vercel의 개발용 프로젝트도 production 빌드이므로 표시되지 않는다.

혼자 시연에서는 기본으로 켜지며, 일반 로컬 방에서는 개발자 도구에서 `localStorage.setItem("hoguk:photo-gate", "on")` 후 새로고침해 선택한다. `off`는 혼자 시연에서도 끈다. 단서·힌트는 실제 대상과 무관한 합성 예시다. 실제 개인 단서는 서버의 `self.mission`을 사용한다.

모의 사진 성공 또는 실패 3회 뒤에 **현재 서버의 정찰원 문제**가 열린다. 사진 완료로 BE 문제·보고·점수를 변경하지 않는다. 일반 choice 퀴즈로의 전환은 별도 코스·서버 작업이다. 실패 후 통과는 `verified:false`로 표시한다. 사진 상태는 메모리만 사용하므로 새로고침하면 초기화되고, 서버 journal/result에는 기록되지 않는다.

## 혼자 시연

로컬 `/api/game/solo`만 사용한다. 서버의 네 자리별 세션으로 화면을 바꿔 보는 방식이며 실제 참가자 역할을 교환하지 않는다. Supabase/Vercel에서는 이 API가 비활성화된다. 응답을 확인하지 못한 요청이 남으면 보직 화면 전환을 막아 다른 자리로 재전송하지 않는다.

네 거점은 로컬 `LOCAL_V2_PRESET=full-course`와 새 `jnu-demo-dev-*` 코스로 확인한다. `full-course-v1`은 FE의 별도 용봉관 시연 문항을 선택하는 옵션이며 기존 코스·정식 콘텐츠를 바꾸지 않는다. 요청은 기존 UTF-8 8KB 제한을 지킨다.

## 검증 범위

단위 테스트와 production 빌드 외에, 분리된 로컬 합성 데이터로 사진 시연·4인 헌화·봉지 완주·개인 나레이션·첫 화면 복귀·429 복구를 검증한다. 실제 기기의 카메라·GPS 현장 검증과 이미지 모델 연결은 별도다.

검증 결과: 단위 테스트 49개 파일·451개 통과. 브라우저 검증은 `full-course`·`solo-route` 4개와 `integrated-v2-home/throttle/narration/scout-scan` 17개, 총 21개 시나리오가 통과했다. 묵념 전환 경합과 문단별 텍스트 검증에서 처음 실패한 2건은 수정 후 해당 항목을 재실행했다. 360px의 긴 나레이션은 마지막 문단까지 스크롤할 수 있고 임무 시작 버튼이 화면 안에 유지된다. 별도 lint 스크립트는 없으며 타입 검사와 production 빌드로 확인한다.
