# BE·Infra 추가 결정 기록

## 2026-10-23 정문 공통·개인 나레이션 분리

- 사용자 요청에 따라 정문 첫 공통 문구를 줄이고, 역할별 개인 임무 안내를 별도 화면으로 연결한다. 실제 문구는 [현재 구현 반영 시나리오](../scenario/GPS_MINO_1st_scenario_current.md)를 기준으로 관리하며 이 문서나 공개 mock에 복사하지 않는다.
- 정문 v2는 공통 `stage.narration`의 `enter` → 본인 `self.mission.intro`의 `enter` → 미션 순서다. 개인 intro가 비어 있거나 진입 장면이 아니면 본인 `self.mission.scenes`의 `enter`만 대체로 사용한다. 본인 미션이나 진입 문구가 없으면 개인 화면을 만들지 않는다. 다른 역할의 안내를 추가 조회하거나 공통 응답에 포함하지 않는다.
- 계속/건너뛰기·ESC는 현재 화면만 넘긴다. 개인 화면의 마지막 버튼은 `임무 시작`이다. 공통·개인 읽음 여부만 game/stage/role별 기기 세션에 분리 저장하고 새로고침 시 읽지 않은 화면부터 이어간다. 안전 도착 화면을 우선하며 나레이션 비활성화는 두 화면 모두에 적용한다. legacy 정문과 다른 거점의 기존 흐름은 유지한다.
- API·DB 변경은 없다. 기존 등록 코스는 불변이므로 수정한 비공개 작성본으로 새 검수 리비전을 등록·활성화하고 웹을 재배포한 뒤 새 방에서 확인한다. 이번 변경에서 코스 등록·활성화·클라우드 배포를 수행하지 않았다. [적용 안내](../fe/GATE_TRIBUTE_INTEGRATION.md)를 따른다.

## 2026-10-11 정문 입력 UI·국화 헌화 선택 통합

- 사용자 요청 범위는 최신 BE에 정문 문제 UI와 추모의 벽 국화 헌화를 연결하는 것이다. 용봉관 UI·BE와 봉지 회고·공동 기록 규칙은 유지한다. 적용 절차는 [정문·헌화 선택 통합 안내](../fe/GATE_TRIBUTE_INTEGRATION.md), 요청 형식은 [API 계약](API_CONTRACT.md#12-pr-5-추모의-벽봉지결과--구현-계약)을 따른다.
- 정문 새 입력 화면은 코스명·ID 접두사로 선택하지 않는다. `stage.id:"gate"`와 서버가 제공한 문항 유형·필드·선행 조건을 읽어 단서 봉투·단계 탭·역할별 입력을 구성한다. `.legacy` 문항은 기존 입력 UI를 유지한다. 답안·기록·개인 단서는 브라우저 저장소에 넣지 않으며 봉투 개방·기록 펼침 여부만 본인 단계 ID로 보관한다.
- 새 wall 계약은 `completion.type:"tribute"`다. 네 명 모두 도착 후 각자 본인 헌화 단계에 `submit-step`, `answer:"confirmed"`를 보내며 공통 `method`·`source`를 생략한다. 성공 시 본인 `report_mask`가 헌화 상태로 갱신되고 마지막 헌화가 사초③·거점 완료를 처리한다. 점수·감점·힌트·별도 보고·공동 기록·`confirm-stage`는 사용하지 않는다.
- 기존 불변 코스의 `completion.type:"confirm"` 조사·보고·공동 기록·전원 확인은 호환 경로로 유지한다. 아래 2026-10-10 공동 확인형 결정은 해당 코스에 계속 적용되며 새 헌화형의 완료 조건으로 가져오지 않는다.
- 전환은 `seed:review` 또는 `seed:course`의 명시적 `--wall-mode tribute`로 새 리비전을 준비한다. 운영 `seed:course`에는 원본과 다른 `--course-id`를 함께 지정한다. 옵션 생략·`preserve`는 기존 wall을 유지한다. 검수 코스의 지정 dev 프로젝트·새 검수 ID·전원 모의 도착 정책과 운영 콘텐츠/GPS 검증은 각각 유지한다.
- 이번 작업에서 작성 원본·기존 방·등록 코스를 덮어쓰거나 코스 등록·활성화·클라우드 배포를 수행하지 않았다. 새 DB 마이그레이션은 추가하지 않는다. 원문·정답·비밀값을 이 문서나 새 공개 예시에 복사하지 않는다.

## 2026-10-10 임시 자료 이미지와 힌트 감점

사용자 결정: 실제 사진은 나중에 제공하며 우선 임시 이미지로 화면을 확인한다. 정문·용봉관 힌트는 1단계 0점, 2단계 사용 시 10점, 3단계 사용 시 추가 10점 감점한다. 한 역할이 3단계까지 사용하면 힌트 감점 합계는 20점이다. 같은 요청 재전송은 기존 멱등성으로 중복 차감하지 않는다. 추모의 벽은 기존대로 모든 힌트가 무료다.

- 직접 만든 로컬 SVG를 정문·용봉관 정찰원 자료사진의 임시 이미지로 사용한다. `임시 이미지 · 실제 현장 자료 아님`을 표시하고 사진을 받으면 코스 `asset.url`과 설명을 교체한다. 누락·로딩 실패에도 임시 이미지와 안내를 표시한다. 기존 개인 정보 공개 범위와 사진 업로드(D6)는 변경하지 않는다.
- 공개 정문 초안의 임시 이미지 URL과 `asset.confirmed:true`는 **임시 그림 사용 승인**만 뜻한다. 실제 현장 사진 검수나 전체 코스 확정을 뜻하지 않는다. 등록 검증의 HTTPS·이미지 승인 조건을 완화하지 않는다.
- 정문·용봉관 작성 데이터의 힌트 감점을 0/10/10으로 반영한다. 무힌트 보너스는 별도 미확정이므로 작성 초안의 `noHintBonus:null`, `scoring.confirmed:false`는 유지한다. 개발용 코스의 기존 합성 보너스 값은 실제 정책으로 확정하지 않는다. D8·D9 역시 별도다.
- 기존 시나리오에는 정답·힌트·판정 기준이 있다. 용봉관 외형 문항의 빈 정답 매핑은 원문 누락이 아니라 개발자 변환 미완료였으며 원문과 선택지를 대조해 비공개 작성 파일에서 채운다. 정문 근거 연결도 앱의 1대1 표현 제약을 원문 자체의 누락으로 단정하지 않는다. 예전 확인 요청서는 그대로 회신 요청에 사용하지 않는다.
- 기존 DB 코스 리비전은 수정하지 않는다. 새 감점 값 적용은 새 리비전 등록·활성 코스 전환 후 만든 방부터다. UI 재배포만으로 기존 코스의 점수가 바뀌지는 않는다. 이 기록은 클라우드 등록·배포 완료 보고가 아니다.

## 2026-10-10 문제풀이 공통 확인 옵션 제거

사용자 확정: 문제를 풀 때 공통으로 붙던 `확인 방식`·`확인한 출처`·`연결할 자료` 입력을 모두 제거한다. 이 결정은 아래 PR-2·PR-4·PR-5 기록의 공통 출처·확인 방식 필수 수집 규칙보다 우선한다.

- FE는 `submit-step`에 `answer`만 보내며 공통 `method`·`source`를 만들지 않는다. 문제 본문의 선택지·근거 연결 퀴즈·기록 필드는 유지한다. 문제 자체의 `answer.source` 필드도 공통 메타데이터 입력과 구분한다.
- 기존 불변 코스의 `sourceRequired:true`와 관계없이 새 서버는 두 항목 생략을 허용하고 공개 문제는 호환 필드 `sourceRequired:false`로 반환한다. 이전 클라이언트가 값을 보내면 허용 방식·출처 형식·자료 ID 범위는 계속 검증한다.
- 수집하지 않은 방식을 현장 확인·해설 완료로 추정하지 않는다. 직접 완료의 `step_progress.method`는 생략하고 기록첩·전달 기록·사초의 method는 미수집 시 `null`로 둔다. 서버 해설 완료만 `explained`를 유지하며 결과 `methods`에는 미수집 값을 넣지 않는다. 기존 거점 완료 경로와 GPS 도착 방식은 별도 의미로 유지한다.
- 용봉관 통신원→암호해독관의 허용된 기록 자동 전달, 선행 문제·보고, 전원 GPS 도착, 힌트·감점·자물쇠 규칙은 유지한다. 실제 정답·문구·개인 기록의 공개 범위도 바꾸지 않는다.
- 이번 변경 자체에는 새 DB 마이그레이션·코스 재등록·비밀값이 필요 없다. 기존 방도 새 서버의 생략 허용 규칙을 사용한다. **Edge를 먼저 재배포한 뒤 웹을 재배포**한다. PR-5 최초 적용 여부는 별도로 확인하며 사용자 완료 보고만으로 각 클라우드 단계·현장 검증까지 완료됐다고 단정하지 않는다.

## 2026-10-10 PR-5 사용자 확정·구현 범위

- 추모의 벽 개인 조사와 봉지 개인 회고 본문은 본인에게만 제공한다. 팀에는 지휘관 공동 낱말·문장·근거와 역할별 완료 상태를 공유한다. 용봉관 자료 전달 예외는 해당 거점에만 유지한다.
