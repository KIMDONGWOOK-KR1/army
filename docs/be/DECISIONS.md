## 2026-10-10 PR-5 사용자 확정·구현 범위

- 추모의 벽 개인 조사와 봉지 개인 회고 본문은 본인에게만 제공한다. 팀에는 지휘관 공동 낱말·문장·근거와 역할별 완료 상태를 공유한다. 용봉관 자료 전달 예외는 해당 거점에만 유지한다.
- 추모의 벽 `memorialRecords`와 봉지 `jointRecords`는 별도 상태다. 초안은 최초 버전 0을 기준으로 생성하고, 실제 내용 변경 때 버전을 올려 전원 확인을 초기화한다. 같은 내용 재저장은 유지한다.
- 봉지 개인 회고 수정 시 기존 공동 초안의 버전도 올리고 네 동의를 초기화한다. 전원이 새 버전 문장·근거를 다시 확인해야 종료된다.
- 결과는 완주·사초·개인 단계 완료/보고 상태·기록 및 교차 확인 건수·힌트/해설·확인 방식·공동 문장을 우선 구현한다. 교차 확인은 선행 보고·자료 연결 문제를 직접 완료한 건수다. 내용 이해를 자동 평가하지 않는다.
- 시간 점수(D8)·랭킹(D9)은 요구를 유지하되 계산식·공개 범위 확정 후 별도로 구현한다. 이번 응답은 null이며 가짜 점수·순위를 만들지 않는다.
- 추모 단계의 점수·감점·숫자·자물쇠·카운트다운·진동·자동 효과음은 사용하지 않는다. 선택형 조용한 머무르기는 서버 완료 조건이 아니다. 퇴장 후 자동 음량 복구도 없다.
- 개발 preset `full-course`는 모의 도착만으로 네 거점 흐름을 시험한다. 추모의 벽 좌표는 미확정 null을 유지하며 전체 GPS 코스는 아직 등록하지 않는다. 기존 두 거점 GPS 코스는 유지한다.
- 사용자 확인: 용봉관 Vercel 재배포와 개발 코스 정문→용봉관 연결 완료. PR-5 클라우드 적용·휴대폰 네 대 현장 시험은 별도다. 적용은 [PR_5_APPLY.md](PR_5_APPLY.md).
- 결정 대기 유지: 공개 코스의 정답 문장 처리, G-01 근거 짝, 실제 자료·사진·점수, 추모의 벽 좌표, D3/D6 및 D8/D9. PR-6은 시작하지 않는다.


## 2026-10-09 PR-4 용봉관 구현과 콘텐츠 등록 준비

- 통신원이 3단계 힌트로 자료 기록 없이 완료하면 암호해독관에게 `explained_without_record`와 `record:null`을 전달한다. 자료를 만들어 채우지 않는다. 암호해독관은 추가 확인 필요 내용을 기록한다. 이미 제출한 기록은 보존한다.
- 개인 정보 분리의 명시적 예외: 용봉관 `Y-02.record`의 허용된 기록 필드·출처·확인 방식만 암호해독관 `self.shared_records` 및 본인의 완료 기록첩으로 전달한다. 지휘관·정찰원·공개 상태에는 이 본문을 보내지 않는다. `Step.recordFrom`은 같은 거점의 타 역할 record 단계이며 같은 `requires`가 있어야 한다.
- 외부 대체 모드(`mode_id:"outdoor"`)는 전원 도착 후 완료 전 언제든 지휘관이 선택한다. 기존 기록·보고·힌트·감점·시도 횟수를 유지하며 사초②와 결과·기록첩에 **외부 대체 조사 · 실내 관람 아님**을 남긴다. GPS 조건은 동일하고 모드 되돌리기는 제공하지 않는다.
- 문장 분류에는 같은 범주를 여러 번 사용할 수 있는 `classification/map-hash`를 추가한다. 기존 `match/map-hash`의 1:1 연결 제약은 유지한다. 지휘관 수정 기록은 `verified`와 `follow_up`을 모두 요구하며 내용 정오를 채점하지 않는다.
- 새 dev preset `gate-yongbong` / `gate-yongbong-gps`는 기존 시연 정문과 합성 용봉관을 연결한다. 전자는 장소 무관 모의 도착, 후자는 각 거점 전원 GPS 도착이다. 합성 코스 prod 금지와 기존 `ANSWER_SALT` 공유 규칙을 유지한다.
- 사용자 요청에 따라 실제 원문을 기반으로 한 등록 준비 파일도 **gitignore된 `private/yongbong-authoring/`에만** 생성했다. 이는 배포 가능한 완성 코스가 아니다. 정찰원 외형 정답과 선택지 연결, 사진 URL·사용 권한, 공식 디지털 자료, 점수 정책, 실제 정문과 합친 새 리비전 검토가 남아 `confirmed:false`로 등록을 차단한다. 실제 문구·정답은 커밋·테스트·PR에 넣지 않는다.
- DB 이벤트 허용 목록 확장은 새 `202610090001_yongbong_alt_mode.sql`로 제공한다. 이미 적용된 마이그레이션은 수정하지 않는다. DB 적용·Edge/웹 배포·새 코스 등록은 사용자가 별도로 수행한다.
- 정문 4대 현장 확인 및 PR #11 병합을 이번 개발 착수의 전제조건으로 두지 않는다. 현장 검증은 보류하며 PR-5는 별도 요청 전까지 진행하지 않는다. [적용 안내](YONGBONG_APPLY.md) 참고.

## 2026-10-09 지정 좌표와 시험 반경 10m 적용

사용자 확정: 정문 (35.172851, 126.905149), 용봉관 (35.175722, 126.906345), 봉지 (35.177269, 126.906604)를 목표 좌표로 고정하고 반경 10m로 시험한다. 이번 사용자 지정에 따라 해당 도착 설정은 `confirmed:true`로 둔다. 이는 콘텐츠·점수·4대 실기기 현장 검증의 확정을 의미하지 않는다.

- `jnu-gps.ts`에 세 목표를 보관하고 현재 구현된 정문 공개 코스와 별도 `v1-gate-gps` dev preset을 연결했다. 용봉관·봉지는 좌표 설정만 준비하며 후속 미션을 구현한 것으로 표시하지 않는다. 추모의 벽 좌표는 미정이고 용봉탑의 GPS 없는 단계는 변경하지 않는다.
- GPS 코스에서는 각자 위치 수신 후 유효 표본 3개 평균·반경 안 5초 유지로 본인 도착을 보고한다. 네 명 모두 도착해야 미션이 열린다. 권한 거부·측위 오류·오래된 위치는 진행을 우회하지 않는다.
- v2 수동·QR 도착을 차단했고, 확정 GPS dev 코스에서도 모의 도착을 차단했다. 기존 GPS 미확정 dev 시연과 로컬 v1 혼자 체험은 유지한다.
- 좌표 원본 CSV·가공 측위 기록은 커밋하지 않는다. 사용자 위치는 브라우저 메모리에서 계산하며 서버에는 도착 결과만 기록한다. 브라우저 보고를 신뢰하는 현재 구조는 유지하고 서버의 실제 위치 인증으로 설명하지 않는다.
- GPS 도착 후 이탈 시 재잠금은 이번 범위가 아니다. 도착 여부·최초 배정 역할은 재접속 시 유지한다.
- DB 변경 없음. 불변 코스의 새 리비전 등록, Edge·웹 재배포 및 실기기 검증은 사용자가 수행한다. [적용 절차](GPS_APPLY.md).

## 2026-10-09 참가자 간 역할 교환 금지

사용자 확정: 실제 4인 게임에서 참가자는 서로 역할을 교환할 수 없다. 최초 배정된 역할을 게임 동안 유지하고 새로고침·재접속으로 다시 배정하지 않는다.

- 이전 시나리오·계획의 30초 교환 창, 상대 동의, 팀당 1회 교환은 이번 결정으로 대체한다. PR-3에서 교환 UI나 `propose-swap`/`respond-swap`을 구현하지 않는다.
- 현재 v2 서버는 교환 액션을 지원하지 않고 `game.swap`을 `{window_ends_at:null, used:false, pending:null}`로 반환한다. 이 비활성 상태를 API 호환용으로 유지하며 교환 요청은 계속 거절한다. 기존 코스 타입의 `roleSwapEnabled`·`roleSwapSeconds` 필드가 교환을 허용한다는 의미는 아니다.
- 앞서 승인한 로컬 dev의 별도 v1 혼자 체험에서 보직을 바꾸는 기능은 시연용이다. 실제 참가자 간 교환과 구분하고 실제 4인 방에 적용하지 않는다.
- PR-3의 우선 범위는 GPS 필수 도착과 기존 출발 흐름의 미연결 부분·재접속 유지 검증이다. 역할 교환은 후속 구현 목록에서도 제외한다.

## 2026-10-09 GPS 필수 진행 정책

사용자 확정: 실제 게임은 GPS 기준으로 해당 거점에 도착해야 진행한다. 기존 정문의 전원 도착 조건과 함께 적용한다. 아래는 PR-3 구현 기준이며 이번 결정 기록만으로 현재 서버 동작이 바뀌지는 않는다.

- 입장·보직 공개·준비는 기존 흐름을 유지한다. 실제 4인 코스의 미션 진입·문제 제출·보고·자물쇠는 네 명의 GPS 도착 조건을 충족한 뒤 허용한다. 도착 전 개인 문제·단서의 응답 공개 범위도 함께 점검한다.
- QR·지휘관 수동 확인·진행자 확인으로 실제 코스의 GPS 조건을 우회하지 않는다. 이전 계획의 D2 `QR → 지휘관 수동(30초)` 대체안은 이 결정으로 대체한다. 방 합류 QR은 도착 확인과 별개이므로 유지한다.
- 앞서 승인한 로컬 dev 시연·dev 합성 코스의 모의 도착은 개발 확인용으로 분리한다. 실제 현장 도착으로 표시하거나 운영 코스에 허용하지 않는다.
- GPS 권한 거부·측위 실패·미확정 좌표이면 미션을 잠근 채 권한 설정·재측정을 안내한다. 좌표 후보를 임의로 confirmed=true로 바꾸거나 현장 반경을 지어내지 않는다.
- 현재 프롤로그의 보직 공개·역할 안내·준비·지휘관 출발은 이미 구현됐다. PR-3은 이를 재구현하지 않고 GPS 필수 진행을 우선 보완한다. P-03 확인 문구의 미연결 부분은 별도 범위로 구분하며 역할 교환은 구현하지 않는다.
- 현재 위치 판정은 클라이언트의 `judgeArrival` 후 `method:gps` 보고를 신뢰한다. 이를 서버가 실제 위치를 검증한 것으로 표현하지 않는다. 위치 데이터 전송·보관 정책을 임의로 바꾸지 않으며 현장 확인 및 API 직접 호출에 대한 보장 범위를 PR-3에서 명시한다.

위 정책은 이후 같은 날의 ‘지정 좌표와 시험 반경 10m 적용’에서 구현했다. 클라우드 배포와 실기기 검증은 별도다.

## 2026-10-09 UI 누락 연결

- 사용자 확정: 자동 시연·보직 전환·장면 건너뛰기는 **로컬 dev의 별도 v1 혼자 체험 방**에서 사용한다. v2 개발 환경에서도 실행할 수 있게 하되 실제 4인 v2 방의 진행 조건은 유지한다.
- 숫자 획득 → 조사·해설 → 자물쇠 왕복, 사초 → 정문 결과 → 기록첩을 연결한다. 완료된 공개 사초 본문·도장과 인증된 본인 기록만 보여 준다. 답안 초안은 메모리로만 유지하고 브라우저 저장소에 추가하지 않는다.
- API 추가: `game.completion`으로 완료 방식을 재조회하고 `self.journal`로 본인 검증 결과·기록·출처·해설을 조회한다. 정답 배열·해시·숫자·전달 단서·타 역할 기록을 포함하지 않는다. 기존 dispatch/CAS/멱등성과 감점·시도 규칙은 유지한다.
- 사초 공개 보상 `char`/`body`는 선택형이며 완료 후에만 제공한다. 기존 불변 코스는 수정하지 않고, 본문 추가 시 새 리비전을 seed와 Edge의 동일한 기존 salt로 등록한다. 새 마이그레이션·비밀값은 없고 Edge·웹 재배포가 필요하다.
- 범위는 정문 UI 복원까지다. 후속 거점 이동·봉지·추모의 벽 공동 기록·전체 코스 결과·랭킹은 후속 PR로 남긴다. 역할 교환은 이후 사용자 결정으로 제외했다. [적용 안내](../fe/UI_RESTORATION.md).
