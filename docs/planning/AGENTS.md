## 반드시 지킬 규칙

### 저장소 공개와 비공개 자료

army 저장소의 공개 설정은 착수 때 확인한다. 공개될 수 있는 저장소를 기준으로 아래 비밀 자료 보호 규칙을 유지한다. 기존 hoguk 저장소와 새 공동 개발 저장소 army를 혼동하지 않는다.

- `.env`, Supabase service role 키, 정답 salt를 커밋하지 않는다.
- **실제 정답은 저장소에 두지 않는다.** `data/courses/jnu.answers.local.json`(`.gitignore`에 추가)에 두고, 시드 스크립트가 해시로 바꿔 DB에 넣는다. 예시 파일의 값은 시안의 시연용 숫자다.

### 정답과 검증

- 정답(숫자, 퀴즈 정답 번호)은 클라이언트 번들과 API 응답 어디에도 넣지 않는다. DB에는 `sha256(salt + site_id + role + answer)`만 저장하고, 비교는 Edge Function에서 한다. salt는 서버 환경변수다. 한 자리 숫자는 경우의 수가 10개뿐이라 salt가 새면 바로 뚫린다.
- 클라이언트는 **자기 역할의 단서만** 받는다. 다른 역할의 단서를 응답에 섞지 않는다.
- 역할 보고는 지휘관 폰에 **✓만** 보낸다. 숫자는 절대 다른 폰으로 보내지 않는다. 말로 전하는 게 이 서비스의 핵심이다.
- 코드 확인과 보직 배정은 Edge Function에서 하고, 멱등이어야 한다(두 번 눌러도 배정은 한 번).

### 자물쇠 규칙 (논문 3.3절)

- 지휘관이 네 자리를 제출하면 서버가 칸별로 검증해 맞은 칸은 잠그고 틀린 칸은 비운다.
- 거점당 **시도 3회**, 틀린 제출마다 **−10점**, 3회를 다 쓰면 **60초 뒤 1회 추가**.
- 시도 횟수, 대기, 점수는 **서버가 센다.** 새로고침으로 초기화되면 안 된다.
- 왜 필요한가: 칸별 피드백만 있으면 0000~9999를 차례로 넣어 최대 10번에 혼자 열 수 있다. 협동 구조가 무너진다.

### GPS 도착 판정 (논문 3.2절과 같아야 한다)

1. `watchPosition({enableHighAccuracy:true, maximumAge:0})`
2. 추정 오차(`accuracy`)가 **40m를 넘는 측위값은 버린다.**
3. 남은 값 중 **최근 3개 좌표를 평균**한다.
4. 평균 좌표와 기준점의 Haversine 거리가 **반경 R 이내로 5초 연속**이면 도착. 반경을 벗어나면 머무른 시간은 0으로 돌아간다.

- R은 거점 데이터의 `radius_m`이다. 기본 30, **10/6 답사 실측 후 확정**한다.
- 판정 코드는 `web/lib/arrival.ts` 한 곳에만 두고 단위 테스트를 붙인다. 실측기(`index.html`의 `judgeState`)와 `analyze_gps.py`의 `detect`와 같은 결과를 내야 한다. 답사 CSV를 테스트 픽스처로 써서 교차 검증한다.
- 위치 좌표는 서버에 저장하지 않는다. 도착했다는 결과만 보낸다.
- 위치를 거부해도 진행은 된다. 팀 위치 계산에서만 빠진다.

### 모바일 브라우저

- iOS는 위치·소리·화면 켜짐 유지를 **사용자가 누른 버튼 핸들러 안에서만** 요청할 수 있다. "장비 수령" 버튼 한 번에 차례로 요청한다.
- 진동은 보조 신호다(iOS 미지원). Wake Lock이 실패해도 앱은 돌아가야 한다.
- 기준 화면 폭 360~430px, 터치 타깃 44px 이상, 직사광선에서 읽히는 대비.

### 콘텐츠 원칙 (논문 3.4절)

- 주적, 특정 국가·집단을 겨누는 표적, 총기·사격 연출은 넣지 않는다. 서사에서 맞서는 대상은 '망각'이다.
- 추모 성격 거점에서는 속도 경쟁을 두지 않고, 희생자 수나 이름을 정답으로 쓰지 않는다.
- 추모 거점 외에는 시간 점수·힌트 감점을 적용하고 팀 랭킹을 제공한다. 상무대 필수 요구다(2026-10-08 PM 정정). "시간 경쟁·순위 없음"으로 구현하지 않는다.
- 5·18 사적지에서는 전술 대형이나 경례 촬영 같은 군사적 연출을 두지 않는다.
- 문구는 시안의 짧은 명령형 톤("~하라")을 따르고 과장하지 않는다.

### 개인정보

- 실명, 연락처, 이메일은 받지 않는다. 호출명(한글·영문·숫자 1~6자)과 기기 토큰만 쓴다.

## 작업 방식

- 작업 브랜치에서 구현하고 `KIMDONGWOOK-KR1/army`에 PR을 올린다. 기본 브랜치 직접 푸시, 작성자·에이전트 임의 머지, 자동 머지는 하지 않는다. 김동욱의 검토·수정 요청을 반영한 뒤 김동욱이 최종 머지한다.
- PR에는 목적·관련 MVP 기능 ID·변경 범위·검증 결과·필요한 캡처·남은 문제를 적는다. 코드 변경은 관련 빌드·테스트·수동 확인, 문서 변경은 내용·날짜·역할·참조 확인 결과를 기록한다. 논문 원고는 이환희가 주작성하고 김동욱이 리뷰한다.
- 기능 단위로 작게 커밋한다. 커밋 메시지는 한국어로 쓴다.
- 확정되지 않은 값은 지어내지 않는다. `TODO(확인필요):` 주석을 달고 데이터에는 `confirmed: false`를 둔다.
- 완료 기준: `npm run build`와 `npm test` 통과, 그리고 브라우저 창 4개(또는 폰 4대)로 입장부터 자물쇠 해제까지 수동 확인.
- 개발 편의 기능은 처음부터 넣는다: `?dev=1`이면 역할 전환, GPS 모의(거리 슬라이더), 타이머 건너뛰기.
