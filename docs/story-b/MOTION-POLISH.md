# 봉투·기록 수집 모션 보완

2026-10-11 · 시작점 `6e09fa1` · `feat/story-b`

단서를 여는 행동과 기록이 수첩에 남는 결과를 화면에서 연결했다. 앞선 [공식 게임 조사와 적용](QUEST-DISCOVERY.md)에 이어, 종이가 실제로 펼쳐지고 이동하는 반응을 보완한 작업이다. 아래 수치는 이 게임의 설계값이다.

## 적용한 변화

| 장면 | 직전 구현 | 이번 구현 |
|---|---|---|
| 단서 개봉 | 봉투가 사라지고 도구가 나타남 | 누른 위치에서 봉인이 풀리고 뚜껑이 젖혀지며 종이가 나옴. 도구는 즉시 사용 가능 |
| 기록 보관 | 제자리에서 도장 표시 | 누른 기록 봉투가 실제 수첩의 해당 단서 칸으로 이동·축소됨. 목적지가 화면 밖이면 현재 위치에서 마무리 |
| 공동 사초 | 기록책 아이콘과 네 보직 문양 | 네 보직의 종이 조각이 기록책 안에서 한 장으로 맞춰짐 |
| 완료 후 조작 | 완료 화면으로 교체 | 현재 보이는 조사의 완료 시 기록 펼치기 버튼에 초점을 옮겨 키보드로 이어서 조작 |

봉인 140ms, 뚜껑 220ms, 종이 240ms, 전체 이동 280ms다. 이동과 투명도의 곡선을 분리해 처음 65% 동안 종이가 보이도록 유지한다. 사초 조각은 240ms 안에 모인다. transform·opacity만 움직이며 종이 모양 자체는 고정이다.

## 힉스필드 사용 판단

사용 가능한 이미지·영상 생성 기능과 관련 스킬을 확인했다. 이번 연출은 터치한 봉투와 현재 수첩 칸의 화면 좌표에 따라 달라져야 하므로 브라우저의 Web Animations API와 CSS로 구현했다. 힉스필드 생성 호출은 하지 않았고 새 이미지·영상·음원이나 라이브러리를 추가하지 않았다. 종이는 창작한 UI 소품이며 실제 사료를 재현한 이미지가 아니다.

## 조작·접근성·보호 범위

- 장식 레이어는 `aria-hidden`이고 포인터를 받지 않는다. 애니메이션 완료를 기다리는 진행 조건이 없다.
- 스크롤·창 크기 변경·다음 입력·다른 단서 선택·화면 이탈·동작 줄이기 설정 변경 시 남은 레이어를 정리한다.
- 키보드 개봉과 동작 줄이기에서는 날아가는 레이어를 만들지 않는다. 기존의 이동 없는 페이드와 즉시 조작을 유지한다.
- 새로고침 복원은 기존 단계 ID의 개봉·보관 기억만 사용한다. 모션은 서버 완료나 정답 판정에 관여하지 않는다.
- 이동 좌표는 DOM 사각형이다. GPS·입력값·정답·개인 기록을 모션으로 복제하거나 저장하지 않는다.
- 기존 코스 5개, 25개 조사와 서버 계약, 추모의 벽, 음원, 3D 지도는 이번 작업에서 변경하지 않았다.

새 모션 시험은 네 독립 세션을 만들고 공개 장식 레이어만 일시 정지해 뚜껑·이동·지속 시간을 검사했다. 해설 경로로 완료시켜 정답 입력 없이 수첩 이동과 완료 후 초점을 확인했다. 다른 단서 선택·스크롤에 의한 취소, 자연스러운 종료, 새로고침 복원, 키보드와 동작 줄이기도 양쪽 브라우저에서 통과했다.

전체 코스 시험은 네 독립 브라우저 세션에서 정문 13개·용봉관 12개 조사와 보고·자물쇠를 거쳐 기존 추모의 벽의 네 사람 헌화, 봉지의 회고·공동 동의, 최종 결과까지 통과했다. 정상 풀이·해설 경로·혼자 체험·나레이션 검사를 포함했다. 폰 폭 320~430px와 글자 130%의 가로 넘침·접근성 검사도 기존 E2E에서 통과했다. 도착은 모의 도착이며 실제 휴대전화 4대나 현장 GPS 시험이 아니다.

중간 프레임을 확인했을 때 종이가 너무 일찍 옅어지는 문제가 있어 이동과 투명도의 곡선을 분리했고, 수정 후 프레임을 다시 확인했다. 이번 최종 검사에 실패한 타입·빌드·단위·E2E 시험은 없다. Playwright 실행에는 색상 환경 변수에 관한 경고가 있었으며 시험 실패는 아니었다. 로컬 3013은 기존 비공개 실행 설정과 방 데이터를 보존해 다시 실행했고 HTTP 200을 확인했다.
