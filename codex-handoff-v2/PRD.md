# PRD 호국실록 전남대 시범판

의뢰처: 상무대 (군학연계) / 형태: 웹앱, QR 접속, 설치 없음

문서 버전: 2026-10-06 회의용 개정안. **2026-10-07 수요일 오후 6시 한국시간 회의**에서 MVP 범위와 세부 분업을 확정하고 이후 개발에 착수한다. 김동욱은 PM·논문/코드 리뷰어·최종 PR 머지 담당, 이환희는 FE·논문 작성 주담당, 장민호·김종연은 BE·Infra 등 개발을 맡는다. 두 사람의 세부 배정은 아직 확정하지 않았다.

공동 개발 저장소는 **[KIMDONGWOOK-KR1/army](https://github.com/KIMDONGWOOK-KR1/army)**다. 담당자가 작업 브랜치에서 변경을 만들고 PR로 제출하면 김동욱이 읽고 검토·수정 요청한 뒤 직접 머지한다. 기본 브랜치 직접 푸시와 작성자·에이전트의 임의 머지는 하지 않는다. 개발 및 논문 수정의 상세 흐름은 `MVP_PLAN.md` 5.4절을 따른다.

개발 규칙은 `AGENTS.md`, 이전 진행 기록은 `HANDOFF.md`, MVP 범위·분업·일정·회의 결정표는 [MVP 개발 기획서](MVP_PLAN.md)를 읽는다. **기존 확정**은 인수인계에서 정한 내용, **사용자 확정**은 이번 대화에서 정한 일정·역할, **회의 제안**은 새로 좁힌 범위나 추가한 계약이다. 회의 제안은 구현 완료나 승인된 정책을 뜻하지 않는다.

화면·문구 참고는 `docs/prototype.html`(1차 시안)이다. 현재 폴더에 없는 파일이므로 PM이 원본을 확보한다. 충돌 시 기능 규칙은 PRD, 화면·문구는 확보한 시안을 기준으로 하되 MVP 제외 기능은 구현하지 않는다. 현재 이 폴더에는 `web/`, GPS 실측기, 분석 스크립트가 없다. 기능 상태는 모두 **미검증**이며 완료는 9장의 증거로 판단한다.

## 1. 개요

4인 1팀, 1인 1폰. 팀이 전남대 정문 → 용봉관을 걸으며 거점마다 역할별로 다른 단서를 푼다. 각자 얻은 숫자는 **자기 폰에만** 보이고, 지휘관 폰의 4자리 자물쇠는 **말로 전해 들은 숫자로만** 열린다(직소 학습, Aronson 1979). 자물쇠를 열면 그 거점의 기록인 '사초'를 얻는다.

- 시범판 범위: 전남대 거점 2곳. 이후 5·18민주화운동기록관 등으로 확장하므로 코스는 데이터로 분리한다(5장).
- 기존 제외 범위: AR, 주적·사격 연출.
- 이번 MVP 제안: **4명·폰 4대·두 거점의 완주**를 필수로 한다. 2~3명 겸임, 카메라 촬영, 소리·Wake Lock, 집결 보너스, 운영자 화면은 후순위로 옮긴다. 장소 원칙과 개인정보 보호는 필수다.
- 검증 목표: 실기기 4대가 입장부터 사초 2개 획득과 종료까지 진행하고, 다른 사람의 단서·숫자가 자동 공유되지 않으며, 자물쇠 횟수·점수가 새로고침 후에도 유지된다.

## 2. 역할

보직은 계급과 무관하게 서버가 무작위로 배정한다. **방장**은 방을 만든 사람이고, **지휘관**은 배정된 보직이다. 방장은 보직 공개를 시작하고 지휘관은 작전 출발·자물쇠·다음 거점 이동을 담당한다. 두 권한을 혼동하지 않는다.

| 보직 | 하는 일 |
|---|---|
| 지휘관 | 자기 단서(퀴즈) + 팀원 보고(✓) 확인 + **자물쇠 입력**, 이동 출발 신호 |
| 정찰원 | 현장 표지석·안내판을 찾아 읽고 답 입력. MVP에서는 사진 촬영·업로드 없이 관찰로 해결 |
| 통신원 | 주파수 맞추기 미니게임 |
| 암호해독관 | 달력·한자 현판 해독 |

**인원이 모자랄 때 겸임 설계 보존**

아래는 기존 설계다. 이번 MVP 필수 범위에서는 제외하는 안을 회의에서 확정한다. 제외 시 4명 미만으로는 시작할 수 없으며 이를 대기실에 표시한다.

- 3명: [지휘관+통신원], [정찰원], [암호해독관]
- 2명: [지휘관+정찰원], [통신원+암호해독관]
- 겸임자는 화면 위 탭으로 두 보직을 오간다.

## 4. 거점 미션 규칙

### 4.1 도착 판정 (논문 3.2절)

- `verifyBy: "gps"`: 오차 40m 초과 측위값 버림 → 최근 3개 평균 → 반경 R 안에 5초 연속이면 도착(벗어나면 0으로). R은 거점별 `radius_m`, 실측 후 확정(기본 30).
- 좌표 평균 전 최근 유효 표본 3개가 모여야 판정을 시작하고 `watchPosition({enableHighAccuracy:true, maximumAge:0})`을 사용한다. 거리 계산은 Haversine, 시간은 측위 타임스탬프를 사용한다.
- **회의 결정 G01:** 원본 실측기·분석 스크립트에서 고오차 값·측위 공백 발생 시 연속 체류 시간 처리 방식을 먼저 확인하고 같은 규칙으로 구현한다. 원본 확보 전에는 GPS 교차 검증 완료로 표시하지 않는다. 오래된 좌표 3개만으로 체류를 인정하지 않도록 경계·공백 테스트를 포함한다.
- `verifyBy: "qr"`: 실내 확장을 위한 데이터 값만 보존한다. 거점 QR 스캔은 이번 MVP 제외이며 방 입장 QR과 구분한다.
- **회의 제안 G02:** 위치 허용 팀원 중 1명 이상 도착하면 팀 도착으로 인정한다. 도착 결과만 서버로 보내고 좌표는 보내지 않는다. 이는 GPS를 이용한 클라이언트 판정이며 서버가 실제 위치를 인증한 것은 아니다.
- GPS 실패·권한 거부 시 지휘관의 "수동 도착"을 제공한다. 서버가 기록한 해당 거점 이동 시작 시각으로부터 30초 후 허용한다. 서버에 `manual=true`로 구분하고 GPS 성공률 계산에서는 제외한다.

### 4.2 역할 단서와 보고

1. 각 폰은 `get-clue`로 **자기 보직의 단서만** 받는다.
2. 단서를 풀고 답을 입력하면 `submit-report`가 해시로 검증한다.
3. 맞으면 서버가 그 보직의 **숫자 한 자리를 그 폰에만** 돌려주고, `reports`에 ✓를 기록한다. 지휘관 폰은 DB 변경 구독으로 ✓만 본다.
4. 틀리면 다시 시도하고 감점하지 않는다. **회의 제안 G03:** 학습용 재시도는 횟수 제한 없이 허용하되 서버에서 동일 멤버의 보고 요청은 초당 1회로 제한한다.
5. 도착 전·다른 거점·다른 보직 요청은 서버에서 거부한다. 성공한 뒤 새로고침해도 `get-game`이 자기 보직의 완료 여부와 자기 숫자를 돌려준다. 다른 팀원의 숫자는 포함하지 않는다.

**회의 제안 제출 규격:** `answer`는 문자열로 통일한다. 퀴즈·한자 선택은 화면 표시와 같은 1부터 시작하는 선택 번호, 주파수는 소수 첫째 자리 문자열, 달력은 `월요일`~`일요일` 중 하나, 현장 찾기는 문자열이다. 시드와 서버 검증은 같은 정규화 함수를 사용한다. 공통적으로 Unicode NFC와 양끝 공백 제거를 적용하고, 주파수는 유효 숫자를 소수 첫째 자리로 변환한다. 현장 답의 내부 공백·대소문자 허용 여부는 문항 데이터에서 명시하며 임의로 바꾸지 않는다. 실제 정답 값은 공개하지 않고 제출 규격만 FE에 전달한다.

### 4.3 자물쇠 (논문 3.3절)

- 지휘관 폰에만 보인다. 칸 순서는 거점 데이터의 `lock_order`(전남대편 두 거점 모두 지휘관·정찰원·통신원·암호해독관).
- 네 칸을 모두 채워 제출 → `open-lock`이 칸별 검증 → 맞은 칸은 잠기고(이후 수정 불가) 틀린 칸은 비움.
- 거점당 3회. 틀린 제출마다 −10점. 3회 소진 시 `next_attempt_at = now + 60s`, 그 뒤 1회 추가(이후에도 같은 규칙 반복).
- 상태(`attempts_used`, `locked_digits`, `next_attempt_at`, 점수)는 서버 DB에 있고, 모든 판단은 서버 시각 기준.
- 네 칸이 맞으면 사초 획득, 다음 이동 단계로.
- **회의 제안:** 네 역할의 보고가 모두 완료된 뒤에만 제출을 허용하고 서버도 이를 확인한다. 지휘관 본인의 퀴즈 보고도 포함한다.
- 같은 제출을 재전송해도 시도·감점은 한 번만 적용한다. 동시 제출은 한 트랜잭션에서 순서대로 판정하고 같은 사초를 중복 지급하지 않는다. 잠긴 칸을 바꾸거나 다음 거점을 미리 제출하면 거부한다.
- 동일 `request_id`의 동시 재전송은 한 제출이다. 서로 다른 ID의 유효 제출은 서버 순서대로 각각 한 시도로 처리한다. FE는 응답 대기 중 제출 버튼을 비활성화하고 재시도에 같은 ID를 사용한다.
- 3회 소진 뒤에는 60초마다 추가 1회만 사용할 수 있다. 그 추가 시도도 실패하면 다시 60초를 기다린다. 대기 중 거부된 요청은 시도·감점에 포함하지 않는다.

### 4.4 점수

- 자물쇠 오답 −10은 기존 확정이다. **회의 제안 G04:** MVP는 100점으로 시작하고 오답 제출마다 10점을 차감하며 최저 0점으로 표시한다. 성공·시간 보너스는 제외한다. 초기값과 하한은 회의에서 확정하며 FE는 서버가 반환한 점수만 표시한다.
- 추모 성격 거점(`reverent: true`)에서는 시간 점수를 주지 않는다.

## 5. 코스 데이터

`data/courses/jnu.json`(공개) + `jnu.answers.local.json`(비공개, gitignore). 시드 스크립트 `web/scripts/seed-course.ts`가 둘을 읽어 공개 정보는 `sites`/`clues`에, 정답은 해시로 `answers`에, 숫자는 `digits`에 넣는다.

JSON의 `radiusM`, `lockOrder`, `verifyBy`를 DB의 `radius_m`, `lock_order`, `verify_by`로 변환하는 책임은 시드 스크립트에 둔다. FE·GPS는 공통 타입으로 변환된 코스 정보를 받는다. 두 거점에 각각 역할 4개의 단서와 정답 대응이 있어야 시드 검증을 통과한다. 실제 코스의 `confirmed: false`, 빈 좌표, 빈 문항은 현장 검증 완료 조건을 만족하지 않는다.

전남대편 내용(시연값, 답사로 확정):

| 거점 | 지휘관 | 정찰원 | 통신원 | 암호해독관 | 코드 | 사초 |
|---|---|---|---|---|---|---|
| ① 정문 | 퀴즈(정답 2번) | '5·18 사적지 제1호' 표지석 | 주파수 51.8 (조형물 '피어나다' 꽃잎 수) | 달력: 18일 → 일요일 → 7 | 2·1·3·7 | 證 증언의 사초 |
| ② 용봉관 | 퀴즈(정답 3번) | 안내판 | 주파수 19.9 (1996년 → 끝자리 6) | 현판 한자 鳳 → 8번 칸 | 3·4·6·8 | 層 겹친 시간의 사초 |

- 좌표, 표지석·안내판 문구, 꽃잎 수, 현판 사진, 도보 시간은 답사 결과로 확정한다. 10/6 답사는 이전 예정 항목이며 실제 진행·확정 여부는 10/7 회의에서 확인한다. 확정 전 값은 `confirmed: false`.
- 분대 대항 퀴즈는 별도 시안, 이번 범위 아님.
- 표의 코드·주파수·요일은 **시연 예시**다. 실제 정답을 FE 코드·공개 JSON·정적 응답으로 복사하지 않는다. 공개 코스 원본을 그대로 앱에 번들링하면 다른 역할 단서도 보이므로, FE는 거점 공통 정보와 자기 역할 단서를 구분해 받는다. 다른 역할의 실제 단서는 번들·응답에 넣지 않는다.

```
clues          site_id, role, payload jsonb            -- 화면에 보여줄 단서 (정답 없음)

digits         site_id, role, digit smallint            -- RLS: 클라이언트 접근 불가
games          id, join_code, status(lobby|briefing|equip|playing|done), host_member_id,
               course_id, current_site_seq, site_phase(travel|mission|cleared), version,
               reveal_at, site_started_at, score, started_at, ended_at, expires_at
team_members   id, game_id, auth_user_id, slot, nickname, roles text[], device_token_hash, ready_at, last_seen
arrivals       game_id, site_id, member_id, manual bool, at
reports        game_id, site_id, role, member_id, ok_at  -- ✓만
lock_state     game_id, site_id, locked_digits smallint[] (null=빈칸), attempts_used, bonus_attempts, next_attempt_at, opened_at
lock_attempts  game_id, site_id, submitted smallint[], correct_mask bool[], at, penalty
game_public    game_id, version, status, site_phase, current_site_seq, score,
               reveal_at, site_started_at, started_at, ended_at,
               report_mask, locked_mask, attempts_left, next_attempt_at, acquired_sites
members_public game_id, member_id, slot, nickname, roles text[], ready_at
request_receipts auth_user_id, function_name, request_id, request_hash, response_private, created_at
```

- 위치 좌표·사진 저장은 이번 MVP에 포함하지 않는다. 실측기는 별도 시험 도구이며 앱 서버에는 도착 여부만 기록한다.
- 위 모델은 **분업을 위한 개정 제안**이다. `game_public`과 `members_public`은 실시간 구독용 별도 테이블로, 서버가 내부 상태와 함께 원자적으로 갱신한다. `lock_state`·`lock_attempts`·`answers`·`digits`·`request_receipts`는 서버 전용이며 같은 팀원에게도 직접 공개하지 않는다.
- 공용 응답·Realtime에는 `report_mask`(✓), `locked_mask`(잠긴 칸 여부), 점수·단계만 보낸다. **잠긴 숫자 자체를 공용 상태에 넣지 않는다.** 지휘관이 제출해 맞춘 숫자는 지휘관 전용 응답에서만 복구한다.
- RLS: 인증된 사용자가 자기 게임의 공개 상태와 공개 멤버 정보만 읽는다. 쓰기는 Edge Function으로 한정한다. 다른 게임의 테이블·Presence·Broadcast 구독은 거부한다. private Realtime 채널의 가입 권한도 게임 소속으로 검증한다.
- **회의 제안 G06:** 이메일·비밀번호 입력 없는 Supabase 익명 인증으로 세션을 만들고 검증된 사용자 ID를 `auth_user_id`에 연결한다. 기기 토큰은 보조 식별값이며 게임 ID·역할·호출명·기기 토큰만으로 권한을 인정하지 않는다. 모든 함수에서 JWT와 게임 소속·역할·단계를 검사한다.
- 같은 브라우저의 인증 세션이 유지되는 동안 새로고침·재연결 시 같은 자리·보직·자기 숫자를 복원한다. 로그아웃·브라우저 데이터 삭제·다른 기기로의 계정 복구는 이번 범위에 포함하지 않는다. 사용자별 응답은 공유 캐시에 저장하지 않는다.
- 중복 방지: `(game_id, slot)`, `(game_id, auth_user_id)`, `(game_id, site_id, role)`의 성공 보고, `(auth_user_id, function_name, request_id)`는 유일해야 한다. 방 생성 전에도 인증 사용자 단위로 재요청을 식별한다. 슬롯 배정·역할 배정·자물쇠 판정·거점 전환은 트랜잭션으로 처리한다.

### 6.1 상태 전환 계약

이 상태·이름은 회의 제안이며 FE와 BE가 같은 값으로 확정한다. `status`는 팀 전체 진행, `site_phase`는 진행 중인 거점 안의 단계다.

| 상태 | 전환 주체와 조건 | 다음 상태 |
|---|---|---|
| `lobby` | 방장이 `start-game`, DB 참가자 4명 등록 | `briefing`, 역할·`reveal_at` 저장 |
| `briefing` | 서버 시각이 `reveal_at` 이상 | `equip` |
| `equip` | 본인 `set-ready`; 4명 준비 뒤 지휘관 `begin-operation` | `playing / travel`, 정문 이동 시작 |
| `playing / travel` | 현재 거점의 유효 도착 요청 | `playing / mission` |
| `playing / mission` | 보고 4개 완료 뒤 서버 자물쇠 해제 | 첫 거점은 `cleared`, 마지막 거점은 `done` |
| `playing / cleared` | 지휘관 `depart-next-site` | 다음 거점 `travel`, 도착·보고·자물쇠는 거점별 새 상태 |
| `done` | 기존 멤버의 결과 조회만 허용 | 종료 상태 유지 |

`briefing`의 시간 경과는 `get-game` 및 후속 변경 함수에서 멱등하게 정상화한다. 별도 예약 작업이나 Broadcast 수신 여부에 의존하지 않는다. 시작 뒤 신규 합류는 거부하고 동일 멤버 복귀만 허용한다. 서버 상태마다 `version`을 증가시켜 FE가 오래된 이벤트를 적용하지 않게 한다. 종료 뒤 늦은 보고·이동·자물쇠 요청은 상태를 변경하지 못한다.

FE는 `reveal_at` 타이머 종료 시 `get-game`을 한 번 호출해 준비 단계로 전환한다. Presence는 온라인 표시를 위한 보조 정보이며 시작 권한의 근거로 쓰지 않는다. 등록 참가자가 일시 단절해도 보직 공개는 가능하지만 네 명이 실제로 준비 완료하기 전에는 작전 출발이 불가능하다.

## 7. Edge Functions와 공통 계약

아래는 기존 함수를 보완한 **회의 제안 계약**이다. FE는 모의 응답부터 구현하되 같은 이름과 필드를 사용한다. 변경 요청은 모두 `request_id`를 포함한다. 동일 ID·동일 내용은 기존 결과를 반환하고, 동일 ID·다른 내용은 `REQUEST_CONFLICT`로 거부한다. 거점 요청은 `site_id`를 포함해 이전 거점의 지연 요청을 차단한다.

| 함수 | 입력 | 하는 일 |
|---|---|---|
| `create-game` | nickname, course_id, device_token | 코드 생성(중복·금지문자 제외), 호출자를 방장으로 등록 |
| `join-game` | code, nickname, device_token | 코드 확인, 빈 슬롯 원자 배정, 연속 실패 차단. 같은 인증 사용자면 기존 자리 반환 |
| `start-game` | game_id (방장만) | MVP는 네 명 한 보직씩 무작위 배정, `reveal_at` 저장·Broadcast. 멱등 |
| `get-game` | game_id | 단서 없는 코스/현재 거점 정보, 공개 상태·본인 상태·본인 숫자 복원. 지휘관에게만 본인이 제출해 잠근 숫자 반환 |
| `set-ready` | game_id, location_permission | 본인 장비 준비 저장. 위치 거부도 준비 완료 가능 |
| `begin-operation` | game_id (지휘관만) | 4명 준비 검사, 작전·첫 거점 이동 시작 시각 저장 |
| `get-clue` | game_id, site_id | 호출자 보직의 단서만 반환 |
| `report-arrival` | game_id, site_id, manual | 도착 기록 |
| `submit-report` | game_id, site_id, role, answer | 해시 비교 → 맞으면 digit을 호출자에게만 반환, reports에 ✓ |
| `open-lock` | game_id, site_id, digits[4] (지휘관만) | 4.3 규칙 처리, 결과(잠긴 칸, 남은 횟수, next_attempt_at, 점수) 반환 |
| `depart-next-site` | game_id, site_id (지휘관만) | 현재 거점 해제 검사, 다음 거점·이동 시작 시각 저장 |

`start-game`의 MVP 제안은 4명에게 한 역할씩 배정하며 겸임은 후순위다. 모든 함수는 입력에 적힌 역할을 신뢰하지 않고 실제 멤버 역할을 조회한다.

공통 성공 응답은 `server_now`, `version`, `game`(공개 상태), `self`(호출자 전용 상태)를 포함한다. `self`는 멤버 ID·보직·준비 여부·본인 완료 보고와 숫자이며, 다른 사람의 단서·정답·숫자는 포함하지 않는다. 자물쇠 배열 순서는 코스의 `lock_order`와 같고 잠기지 않은 칸은 `null`이다.

`get-game`은 추가로 `course`(ID·이름·거점 수)와 `current_site`(ID·순서·이름·좌표·반경·도착 방식·잠금 순서·사초 이름·도보 시간)를 반환한다. 단서·정답·숫자는 이 공통 정보에 넣지 않는다. FE·GPS는 여기서 현재 거점 데이터를 받으며 원본 JSON 전체를 가져오지 않는다.

함수별 추가 결과는 `get-clue`의 `self.clue`(본인 미션 유형·문항·선택지 등), `submit-report`의 `result.ok`와 성공 시 본인 `result.digit`, `open-lock`의 지휘관 전용 `self.lock`(칸별 결과·제출해 잠근 숫자·가능 시각)로 제안한다. 오답 보고에서는 숫자를 반환하지 않는다. 실제 필드 타입은 BE 관리 공통 타입·모의 응답에 동일하게 반영한다.

공통 오류는 `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_CODE`, `ROOM_FULL`, `WRONG_STAGE`, `STALE_SITE`, `NOT_READY`, `REPORTS_INCOMPLETE`, `COOLDOWN`, `RATE_LIMITED`, `REQUEST_CONFLICT`다. 오류는 `code`, 사용자용 `message`, 필요한 경우 `retry_at`을 반환한다. 오답은 학습 결과로 반환하며 시스템 오류와 구분한다.

Realtime: 대기실 접속·끊김은 Presence, 보직 공개·이동 연출은 Broadcast, ✓·잠긴 칸 여부·사초·단계 전환은 공개 테이블 DB 변경 구독이다. 정답과 숫자는 보내지 않는다. 재연결·화면 복귀·새로고침 시 `get-game`으로 복구하며 `server_now`를 기준으로 대기 시간을 계산한다. 임의 숫자가 아닌 서버가 확정한 상태로 UI를 갱신한다.

## 8. 비기능

| 항목 | 기준 |
|---|---|
| 지원 | iOS Safari, Android Chrome 최신 |
| 동기화 | 네 폰 화면 전환 지연 1초 이내(같은 와이파이·LTE 기준) |
| 화면 | 폭 360~430px, 글자 16px 이상, 터치 타깃 44px 이상, 고대비 |

- 동기화 1초 이내는 **목표**다. 실제 4기기에서 보고·단계 변경 시각을 확인하기 전에는 달성으로 쓰지 않는다.
- 개발용 `?dev=1` 역할·GPS·시간 모의는 개발 환경과 격리된 테스트 게임에서만 허용한다. 운영 게임의 인증·자물쇠 시도·서버 대기를 우회하지 않는다. 모의 판정 기록은 현장 GPS 시험과 구분한다.
- API 실패 시 현재 화면을 유지하고 재시도 상태를 표시한다. 요청 결과가 불명확하면 같은 `request_id`로 재조회·재시도해 감점을 중복하지 않는다.
