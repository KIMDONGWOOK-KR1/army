## 1. 제품 목적과 성공 기준

상무대 군학연계 프로젝트의 설치 없는 보훈·역사 현장 교육 웹 서비스다. 강의를 듣거나 한 사람이 문제를 모두 푸는 상황을 줄이기 위해 네 역할에 서로 다른 정보를 배분한다. 각자가 현장의 단서를 풀어 숫자 한 자리를 얻고, 이를 구두로 지휘관에게 전달해야 팀이 다음 거점으로 진행한다.

MVP는 이 협동 구조가 실제로 작동하는지 확인할 수 있어야 한다. 사용자는 QR이나 입장 코드로 접속하며 이메일·실명·연락처를 입력하지 않는다. 단서와 획득 숫자는 본인에게만 보이고, 지휘관은 다른 사람의 보고 완료 표시만 받는다. 서버가 자물쇠 정답·시도·감점·대기를 판정한다.

성공은 네 기기의 입장부터 두 거점 완주까지의 동작으로 판단한다. 실시간 화면 전환 1초 이내는 목표이며 측정 전 달성으로 표시하지 않는다. 작동하는 시제품을 만들었다는 사실과 협동 참여·학습 효과를 입증했다는 사실은 구분한다.

## 2. 현재 준비 상태와 착수 조건

| 자료 또는 기능 | 확인된 상태 | 회의 전후 필요한 일 |
|---|---|---|

| 10/5 아이폰 GPS 기록 | CSV 존재, 임의 장소의 사전 시험 | 판정 개발 자료로만 사용, 현장 논문 수치로 사용하지 않음 |
| 코스 JSON | 두 거점·네 역할 구조 존재 | 좌표·문항·사진·숫자 대응·반경은 현장 확인 필요 |

외부 클라우드 사용 가능 여부와 계정 명의는 상무대 확인 대기 사항이다. 승인이 필요한 환경의 운영 배포는 해당 조건을 먼저 확인한다. 준비가 안 되었을 때는 로컬·격리 시험 환경으로 연결을 검증하고 외부 운영 완료로 보고하지 않는다.

## 3. MVP 기능과 제외 범위

**회의 권고안은 논문 핵심 기능을 포함하는 4인·두 거점 MVP다.** 정문 한 거점만 동작하는 버전은 중간 통합 목표로 사용하고, 일정 부족 시 논문 표현을 조정하는 축소 시연안으로 남긴다. 겸임·운영 화면·확장 코스를 함께 만드는 안은 이번 제출 전 범위에서 제외한다.

### 3.1 필수 기능

P0는 MVP 완료에 모두 필요한 기능이다. 아래의 BE·Infra/GPS 담당 표기는 세부 분업 제안에 따른 작업 분야이며 실명 배정은 5장과 8장에서 확정한다.

| ID | 기능 | MVP 범위와 완료 기준 | 주 담당 분야 |
|---|---|---|---|
| F01 | 입장과 참가자 식별 | 호출명 1~6자, 방 코드·입장 QR, 최대 4명. 새로고침 후 같은 참가자로 복귀하고 5번째 참가자는 거절 | FE + BE |
| F02 | 대기실과 역할 배정 | 네 참가자·접속 상태 표시. 방장만 시작하고 서버가 네 보직을 한 번 배정. 공통 시각에 공개 | FE + BE |
| F03 | 준비와 출발 | 버튼으로 위치 요청. 거부해도 준비 완료. 네 명 준비 후 지휘관만 작전 시작 | FE + BE |
| F04 | GPS 도착 | 오차 40m 필터·최근 3좌표 평균·반경 안 5초. 팀 도착은 한 명 이상을 인정하는 회의 제안. 수동 도착은 별도 기록 | GPS + FE + BE |
| F05 | 역할별 미션 | 지휘관 퀴즈·정찰원 현장 관찰·통신원 주파수·암호해독관 달력/한자. 서버가 자기 역할 단서만 제공 | FE + BE + PM 콘텐츠 |
| F06 | 정답 보고와 정보 분할 | 답을 서버 검증, 숫자는 본인 폰에만 표시. 지휘관은 다른 보고의 ✓만 확인. 본인 숫자는 새로고침 후 복원 | BE + FE |
| F07 | 지휘관 자물쇠 | 칸별 정답 고정·오답 비움. 3회·오답 −10·60초 대기·추가 1회. 서버에서 상태 유지, 중복 제출 중복 감점 없음 | BE + FE |
| F08 | 사초와 다음 거점 | 정문 사초 획득 후 지휘관이 용봉관 이동 시작. 같은 미션 구조를 데이터로 바꿔 재사용 | BE + FE |
| F09 | 작전 종료 | 사초 2개·서버 점수·소요 시간 표시. 신규 입장 코드 만료, 기존 팀원의 결과 조회 가능 | BE + FE |
| F10 | 실시간 공유와 복구 | 대기실·보직·✓·잠금 여부·거점·종료 공유. 연결 복귀 시 서버 상태를 읽고 늦은 이벤트 무시 | BE + FE |
| F11 | 접근 권한과 비공개 정답 | 타 게임·타 보직 접근 차단. 실제 정답·salt·service role 키 비공개. 공용 테이블·채널에 숫자 없음 | BE + Infra |
| F12 | 배포와 검증 | HTTPS 시험 주소, 빌드·판정 테스트, 실기기 4대 두 거점 완주와 증거 기록. GPS 모의는 별도 표시 | Infra/GPS + 팀 전체 |

### 3.2 역할별 최소 화면

| 앱 보직 | 화면에서 하는 일 | 정답 처리 |
|---|---|---|
| 지휘관 | 현장 역사 퀴즈 선택, 자기 보고, 팀 ✓ 확인, 네 자리 입력·출발 | 자신의 퀴즈도 서버 검증, 자물쇠는 별도 서버 함수 |
| 정찰원 | 표지석·안내판을 직접 찾아 읽고 답 입력 | 사진 업로드 없이 서버가 답 검증 |
| 통신원 | 현장 힌트를 읽고 주파수 조절값 제출 | 클라이언트에 목표 주파수를 하드코딩하지 않음 |
| 암호해독관 | 정문 달력 또는 용봉관 한자 선택·해독 결과 제출 | 서버 검증 후 자기 숫자 표시 |

실제 문항과 숫자 대응은 PM의 답사 확인 후 비공개 정답 파일로 전달한다. 현재 JSON과 PRD 표의 시연값을 실제 정답으로 간주하지 않는다. 화면은 360~430px 휴대폰에서 읽을 수 있도록 짧은 문구와 44px 이상 터치 영역을 사용한다.

### 3.3 이번 MVP에서 제외하는 기능

후순위 제안은 2~3인 겸임, 끊김 2분 뒤 자동 겸임, 카메라 촬영·사진 업로드, 효과음·Wake Lock, 고급 애니메이션, 집결 보너스, 분대 이름·마크, 분대 대항 퀴즈, 운영자 관제, 실내 거점 QR, 전남대 외 코스다. 기본 역할 공개와 진행 피드백은 구현하되 장식적 효과의 완성도를 완료 조건으로 삼지 않는다.

AR, 주적·총기·사격 연출은 기존 제품 방향에서 제외되어 있다. 추모 거점의 속도 경쟁, 희생자 수·이름을 정답으로 쓰는 미션, 5·18 사적지의 전술 대형·경례 촬영도 넣지 않는다.

## 4. 사용자 흐름과 예외 처리

정상 흐름은 **방 만들기 또는 합류 → 대기실 → 보직 공개 → 장비 준비 → 정문 이동·도착 → 역할 미션·보고 → 지휘관 자물쇠 → 정문 사초 → 용봉관 이동·도착 → 역할 미션·자물쇠 → 사초 2개·종료**다. FE의 화면 이름과 BE의 상태 값은 PRD 6.1절을 함께 사용한다.

| 상황 | 사용자가 보는 동작 | 서버 처리 |
|---|---|---|
| 인원 부족·방 가득 참 | 시작 대기 또는 합류 불가 안내 | 4명 시작 조건·최대 슬롯 검증 |
| 위치 거부·GPS 실패 | 준비는 가능, 지휘관 수동 도착 안내 | 거점 이동 시작 30초 후 수동 허용, GPS와 구분 |
| 다른 역할 답 제출 | 권한 안내, 숫자 공개 안 함 | 게임 소속·보직·거점·단계 검사 |
| 자물쇠 일부 오답 | 맞은 칸 고정, 틀린 칸 비움, 남은 횟수·점수 표시 | 칸별 결과·감점·다음 가능 시각 저장 |
| 대기 중 새로고침 | 동일한 잠긴 칸·대기·점수로 복귀 | 서버 시각·기존 상태 재조회 |
| 연결 단절·응답 유실 | 연결 안내·재시도, 복귀 시 최신 상태 | 동일 요청 ID 재처리 방지, 상태 버전 확인 |
| 종료 후 늦은 요청 | 종료 결과 유지 | 추가 보고·이동·자물쇠 변경 거부 |

익명 세션 복구 보장은 같은 브라우저에서 인증 세션이 유지되는 경우다. 브라우저 데이터를 지우거나 다른 기기로 바꾼 참가자 복구는 이번 범위에 포함하지 않는다. 권한 오류나 네트워크 오류를 오답 감점으로 처리하지 않는다.

## 5. 팀 분업과 전달물

### 5.1 책임 배정

| 사람 | 확정된 역할 | 세부 책임과 산출물 | 배정 상태 |
|---|---|---|---|
| 김동욱 | PM·리뷰어·PR 머지 | MVP·우선순위·미결정 관리, 시안·현장 콘텐츠 확보, 답사·시험 조율, 상무대 확인, 기능별 완료 증거 관리. 논문과 개발 PR을 검토하고 수정 요청·최종 머지 수행 | 사용자 확정 |
| 이환희 | FE·논문 작성 주담당 | 모바일 화면 전체, 역할 미니게임, 공통 상태 표시, 실시간·GPS 연결 UI, 오류·재접속 화면, 실제 캡처. 논문 본문·표·그림 작성, 김동욱·교수 검토 의견 반영, 제출본 준비 | 사용자 확정 |
| 장민호 | BE·Infra 등 개발 | **제안: BE·DB 책임.** DB·RLS·세션, 방·역할·보고·자물쇠·단계 함수, Realtime 공개 상태, API 모의 응답·서버 검증 | 세부 배정 회의 확정 |
| 김종연 | BE·Infra 등 개발 | **제안: Infra·GPS·QA 책임.** 앱 기반·HTTPS 배포·환경 설정, GPS 판정·CSV 교차 검증, 코스 시드, 통합 시험·결함 기록 | 세부 배정 회의 확정 |

장민호와 김종연은 숙련도와 가용 시간에 따라 위 묶음을 교환·조정한다. 김동욱은 PM과 리뷰를 맡고, 이환희는 FE와 논문 작성을 함께 맡는다. 개발자는 기능별 구현 설명·측정 결과·캡처를 이환희에게 제공한다. 이환희가 원고를 작성하면 김동욱이 구현 사실·논리·표현을 검토하고, 이환희가 의견을 반영한다. 회의에서 FE와 논문 작성에 필요한 가용 시간을 함께 확인한다. 테스트는 전원이 참여하되 FE·BE·GPS 모듈별 최종 수정 책임자는 한 명씩 둔다.

### 5.2 병렬 개발 작업 묶음

W02에서 앱 기반을 넘기면 FE·BE·GPS는 서로 다른 영역을 맡는다. 추천 경계는 FE `web/app`·`web/components`, BE `web/supabase`, GPS·Infra `web/lib/arrival.ts`·테스트·`web/scripts`·배포 설정이다. 공통 타입·패키지 설정·환경변수 변경은 담당끼리 먼저 합의하고, 공통 타입의 최종 관리자는 BE 담당으로 제안한다.

### 5.3 착수 전 공통 계약

회의 종료 시 아래 항목을 FE·BE·GPS 담당이 같은 문서로 확인한다. 기능 구현 전에 모의 응답을 만들면 서버를 기다리지 않고 화면 개발을 진행할 수 있다.

1. 세션·게임 소속·방장·지휘관의 권한 구분과 재접속 범위.
2. PRD 6.1절 상태 이름, `game_id`·`site_id`·역할 enum·배열 순서.
3. PRD 7장 함수 이름, `request_id`, `server_now`, `version`, `game`, `self`, 오류 코드.
4. 공용 상태는 ✓·잠김 여부만, 개인 응답은 자기 단서·자기 숫자만 제공.
5. GPS 모듈은 `siteId/lat/lng/radiusM`과 측위값·타임스탬프를 받아 거리·체류·도착 결과를 반환. 거점 변경 시 판정기를 초기화하고 FE는 도착 결과만 BE로 전송.
6. 공통 타입은 한 곳에서 관리. 테스트용 모의 응답은 실제 정답 없이 성공·오답·대기·연결 실패 상태를 재현.

### 5.4 GitHub 협업과 PR 검토

공동 개발의 기준 저장소는 **[KIMDONGWOOK-KR1/army](https://github.com/KIMDONGWOOK-KR1/army)**다. 개발자와 작업 에이전트는 작업 결과를 이 저장소의 PR로 제출하고, **김동욱이 읽고 검토한 뒤 직접 머지한다.** PR 작성자가 임의로 머지하거나 자동 머지를 켜지 않는다.

1. 원격의 기본 브랜치와 최신 머지 상태를 확인한 뒤 기능 단위 작업 브랜치를 만든다. 브랜치 예시는 `feat/lobby`, `feat/server-lock`, `feat/gps-arrival`, `docs/paper-draft`이며 이름은 제안이다.
2. 자기 작업 브랜치에서 구현·문서 수정·관련 검증을 수행하고 한국어 커밋 메시지로 기록한다. 기본 브랜치에 직접 푸시하지 않는다.
3. army 저장소에 PR을 만들고 김동욱에게 리뷰를 요청한다. PR에는 목적, 관련 기능 ID, 변경 범위, 검증 결과, 화면 변화와 미해결 사항을 적는다. 이른 공유가 필요하면 Draft PR로 올리고 검토 가능한 상태에서 Ready로 바꾼다.
4. 김동욱이 코드·설계·논문과의 일치·검증 결과를 읽고 수정 요청 또는 승인 의견을 남긴다. 작성자가 같은 PR 브랜치에 수정 내용을 추가하고 필요한 검증을 다시 수행한다.
5. 김동욱이 검토한 최종 변경을 머지한다. 다른 개발자는 머지된 기본 브랜치를 반영하고 다음 작업을 이어간다. 통합 시험 기록에는 머지된 커밋 또는 PR을 남긴다.

코드 PR은 변경과 관련된 빌드·테스트·수동 확인 결과를 포함한다. 문서 PR은 내용·날짜·역할·참조를 확인하고, 논문 원고처럼 차이를 읽기 어려운 파일은 변경 요약과 검토용 본문 또는 미리보기를 함께 제공한다. 실제 정답·비밀 키·개인별 원시 위치 자료는 PR에 포함하지 않는다.

논문 수정도 같은 흐름으로 진행한다. 이환희가 원고 변경을 정리해 PR을 올리고 김동욱이 검토한 뒤 머지한다. 김동욱의 내부 검토 후 교수 검토 의견을 받고 이환희가 반영한다. 교수 검토가 김동욱의 PR 검토·머지 책임을 대체하지 않는다.

이 문서의 협업 규칙과 실제 GitHub 설정은 구분한다. 저장소 접근 권한·기본 브랜치·검토 요청 계정·보호 설정과 기존 자료의 배치는 착수 때 확인하며, 업로드와 PR 생성은 각각 실제 실행 결과로 확인한다.

## 7. MVP 검수 시나리오

각 결과에 실행 날짜·버전·기기·확인자·통과 여부를 남긴다. 브라우저 창 4개는 개발용 점검이고 최종 확인은 실기기 4대에서 한다. iOS Safari와 Android Chrome을 포함하는 구성을 권장하며 실제 사용 기기는 회의에서 확보한다.

- [ ] **F01** 같은 방에 네 명이 합류하고 다섯 번째는 거절된다. 동시에 마지막 슬롯에 합류해도 인원이 네 명을 넘지 않는다.
- [ ] **F02** 방장만 시작할 수 있고, 중복 시작 요청에도 역할은 한 번만 배정된다. 네 기기의 역할 공개와 진행 상태를 확인한다.
- [ ] **F03** 위치 권한을 거부한 참가자도 준비 완료할 수 있다. 네 명 준비 전 또는 지휘관이 아닌 경우 출발이 거절된다.
- [ ] **F04** 오차 필터·평균·5초 체류·반경 이탈·측위 공백을 단위 테스트한다. 실측기·분석 스크립트·앱의 같은 CSV 결과를 비교한다.
- [ ] **F04** 현장 진입·스치기 시험을 GPS 모의·수동 도착과 나눠 기록한다. 수동 도착은 서버 30초 이전에 거절된다.
- [ ] **F05/F06** 각 폰에 자기 단서만 보이고 정답 후 자기 숫자만 나온다. 다른 보직·다른 게임 요청과 미도착 보고는 거절된다.
- [ ] **F06** 지휘관에게 다른 사람의 숫자 대신 ✓만 보인다. 팀원 새로고침 후 자기 완료 숫자가 복원된다.
- [ ] **F07** 일부 오답 제출에서 맞은 칸만 잠긴다. 3회 소진·−10 감점·60초 대기·추가 1회를 서버 시각으로 확인한다.
- [ ] **F07** 동일 요청 ID의 중복/동시 재전송은 한 번만 적용한다. 다른 ID의 유효 제출은 서버 순서대로 각각 한 시도로 처리한다. 사초는 중복 지급되지 않고 대기 중 새로고침해도 잠긴 칸·점수·가능 시각이 유지된다.
- [ ] **F08/F09** 정문 이후 용봉관으로 이동해 사초 2개로 종료한다. 종료 뒤 늦은 변경 요청은 거절하고 기존 멤버의 결과 조회는 가능하다.
- [ ] **F10** 연결 단절·화면 복귀 후 서버 상태로 돌아온다. 늦게 도착한 이전 이벤트·이전 거점 요청이 현재 진행을 되돌리지 않는다.
- [ ] **F11** 공용 응답·Realtime·번들에 실제 정답·다른 역할 단서·숫자가 없다. 타 게임 구독과 서버 전용 테이블 접근이 거절된다.
- [ ] **F12** 빌드와 필수 테스트를 통과하고 실제 휴대폰 4대 두 거점 완주를 기록한다. 운영 환경에서 개발용 역할·시간 우회가 되지 않는다.

MVP 완료는 위 항목이 모두 통과한 상태다. 차단 결함은 통합 실패, 정답/권한 노출, 서버 횟수·감점 불일치, 정상 재접속 복구 실패, 두 거점 완료 불가다. PM은 미통과 항목을 완료로 바꾸지 않고 기능별 현황에 남긴다.

| G09 | 시안·답사·실제 콘텐츠 | 원본 시안, 좌표·반경·사진·문항·정답 대응, 준비 여부 확인 | PM | 미결, 회의에서 확보 시한 결정 |

위 표는 아직 회의 결과가 아니다. 결정 후 `제안/미결`을 `확정: 내용, 결정일`로 바꾸고 PRD의 같은 항목도 함께 수정한다. 실제 좌표·정답·평가 수치는 근거 없이 채우지 않는다.

## 9. 구현 증거와 논문 대응

| 논문 주장 | 필요한 실제 증거 | 부족할 때 처리 |
|---|---|---|
| 4폰 실시간 협동 구현 | 같은 팀 네 기기의 역할·✓·단계 변경 기록 | 확인된 부분만 시제품 구현, 나머지는 설계로 서술 |
| GPS 도착 판정 | 판정 테스트·실측 CSV 일치, 실제 거점 진입/스치기 결과 | 모의 시험과 구분, 성능 수치 미기입 |
| 서버 검증·정답 비공개 | 역할 권한 검사·응답 확인·자물쇠 감점/대기/복구 기록 | 클라이언트 시안만 있으면 서버 구현으로 쓰지 않음 |
| 데이터 기반 두 거점 | 같은 화면에 정문·용봉관 데이터 적용 후 완주 | 동작한 거점 수를 명시, 두 거점 구현 주장 조정 |
| 교육 효과·참여 평가 | 실제 참가 인원·절차·설문·사전후 자료 | 하지 못한 평가를 결과로 작성하지 않고 향후 계획으로 정리 |

10/9 중간 점검에 실시간 동기화·서버 자물쇠 중 하나라도 구현·검증되지 않으면 해당 기능의 “구현하였다”를 “설계하였다”로 조정한다. 김동욱이 증거와 주장을 검토하고 이환희가 원고를 수정한다. 논문 표·그림·초록·결론도 같은 실제 범위를 사용한다. 구현 완료와 평가 완료를 별도 관리하고, 측정하지 않은 결과나 인원을 추정해서 넣지 않는다.

PM의 기능 현황 기록은 **기능 ID / 담당 / 구현 상태 / 검증 상태 / 증거 경로 / 결함 / 논문 문구**를 포함한다. GPS 원시 좌표가 있는 시험 자료나 비공개 정답을 공개 캡처·공유 문서에 실수로 포함하지 않도록 증거의 공개 범위를 확인한다.

## 10. 회의 후 첫 작업

1. **김동욱:** 회의 결정표 갱신, 시안·현장 자료 확보 담당과 시한 기록, 콘텐츠를 공개 자료와 비공개 정답으로 나눠 전달한다.
2. **이환희:** 공통 타입·모의 응답으로 입장→대기실→보직→준비 화면부터 구현하고, 역할 미션·자물쇠에 필요한 응답을 BE 담당과 확인한다. 논문 작성 주담당으로서 원고의 미완 항목·필요한 증거·작성 일정을 정리한다.
3. **BE 담당:** 세션·DB·권한·방/역할 API와 공용 상태를 우선 제공한 뒤 보고·자물쇠·전환을 연결한다. FE에 성공·오답·대기·권한 오류 모의 응답을 전달한다.
4. **Infra·GPS 담당:** 앱 기반·시험 환경과 GPS 모듈을 준비하고 원본 판정기·CSV 교차 검증을 시작한다. 4기기 통합 점검 주소와 기록 방식을 공유한다.

첫 통합 목표는 정문 한 거점의 전 과정이다. 두 번째 거점을 붙이기 전에 역할별 응답 분리, 서버 자물쇠, 새로고침 복구를 확인한다. 문서에 적힌 명세만으로 구현을 완료 처리하지 않는다.

개발·논문 담당자는 기능 또는 문서 단위로 army 저장소에 PR을 제출한다. 김동욱은 이를 검토하고 수정 의견을 전달한 뒤 최종 머지한다.
